# Plan 03-01: Split terminal payment into 3 short-lived steps

## Objective
Replace the single long-running POST /api/kiosk/sale (which pushed to terminal, polled for up to 180s, and created a Zoho invoice in one request) with 3 short-lived HTTP requests that avoid gateway timeouts and give the frontend control of the polling loop.

## Architecture: Before vs After

**Before (single request):**
```
Frontend → POST /api/kiosk/sale → [validate → terminal push → poll 5s×36 → create invoice → record payment] → 201 result
```
One HTTP request lasting up to 180s. Railway gateway timeout at ~60s killed the connection.

**After (3 short requests):**
```
Frontend → POST /api/kiosk/sale → [validate → terminal push] → 202 pending          (~1-2s)
Frontend → GET /api/kiosk/sale/status?ref=X → [single Redis check] → pending/result  (~100ms, polled every 3s)
Frontend → POST /api/kiosk/sale/confirm → [create invoice → record payment] → 201    (~2-3s)
```
Each request completes well within gateway timeout. Frontend controls the polling loop.
