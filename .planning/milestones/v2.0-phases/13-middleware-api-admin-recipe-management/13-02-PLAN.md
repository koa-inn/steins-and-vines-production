Create `zoho-middleware/routes/recipes.js` following the patterns from 13-PATTERNS.md:

**File structure:**
```
'use strict';
var express = require('express');
var cache = require('../lib/cache');
var log = require('../lib/logger');
var C = require('../lib/constants');
var axios = require('axios');
var router = express.Router();
var RECIPES_CACHE_TTL = 600; // 10 minutes per D-09
```

**Helper functions:**

1. `callAppsScriptGet(action, params)` -- Builds URL with `APPS_SCRIPT_URL + ?action= + &server_token= + params as query string`. Uses `axios.get(url, { timeout: 15000, maxRedirects: 5 })`. Returns `resp.data`. Logs warning and rejects if `APPS_SCRIPT_URL` or `APPS_SCRIPT_SERVER_TOKEN` not set.

2. `callAppsScriptPost(action, payload)` -- Uses `axios.post(APPS_SCRIPT_URL, JSON.stringify(Object.assign({}, payload, { action: action, server_token: token })), { headers: { 'Content-Type': 'application/json' }, timeout: 15000, maxRedirects: 5 })`. Returns `resp.data`.

3. `bustRecipeCache(recipeId)` -- Deletes `CACHE_KEYS.RECIPES_TS` + all four status-variant list keys (`CACHE_KEYS.RECIPES + ':' + status + ':0:0'` for `all`, `draft`, `active`, `inactive`) + optionally the per-recipe key `CACHE_KEYS.RECIPES + ':' + recipeId`. Returns `Promise.all(keys.map(function(k) { return cache.del(k); }))`.

**Six route handlers:**

1. `router.get('/api/recipes', fn)` -- Extract `status` (default `'all'`), `limit` (default `0`), `offset` (default `0`) from `req.query`. Build `cacheKey = C.CACHE_KEYS.RECIPES + ':' + status + ':' + limit + ':' + offset`. Cache check -> if hit return `{ source: 'cache', recipes, total }`. If miss, call `callAppsScriptGet('get_recipes', { status, limit, offset })`, extract `data.data`, cache the payload at `RECIPES_CACHE_TTL`, also set `CACHE_KEYS.RECIPES_TS` to `Date.now()`. Return `{ source: 'apps-script', recipes: payload.recipes || [], total: payload.total || 0 }`. Catch: `log.error('[api/recipes] ' + err.message)`, `res.status(502).json({ error: 'Unable to fetch recipes' })`.

2. `router.get('/api/recipes/:id', fn)` -- Extract `recipeId` from `req.params.id`. Cache key `C.CACHE_KEYS.RECIPES + ':' + recipeId`. On hit return cached. On miss call `callAppsScriptGet('get_recipe', { recipe_id: recipeId })`. If `!data.ok` return `res.status(404).json({ error: data.message || 'Recipe not found' })`. Otherwise extract `data.data`, cache at `RECIPES_CACHE_TTL`, return `{ recipe: data.data.recipe || data.data, ingredients: data.data.ingredients || [] }`. Catch: 502.

3. `router.get('/api/recipes/:id/availability', fn)` -- Extract `recipeId`. First call `callAppsScriptGet('get_recipe', { recipe_id: recipeId })` to get ingredients with `item_id` values (API-02: server fetches, never client). Then call `cache.get(C.CACHE_KEYS.INGREDIENTS)` for the ingredient stock cache. If ingredients cache is null, return each ingredient with `status: 'unknown'`, `stock_on_hand: null`, `batches_possible: null` and summary `'unknown'`. If cache is warm, build `stockMap` keyed by `String(item.item_id)` -> `item.stock_on_hand || 0`. For each recipe ingredient, compute `batches_possible = needed > 0 ? Math.floor(stock / needed) : 999` and `status = batches === 0 ? 'out' : batches < 3 ? 'low' : 'ok'` (D-08 threshold). Compute `summary`: if any `'out'` -> `'cannot_brew'`; if all `'ok'` -> `'all_ok'`; else `'some_low'`. Return `{ recipe_id, summary, ingredients: [...] }`. Catch: 502.

4. `router.post('/api/recipes', fn)` -- Extract `payload` from `req.body`. Call `callAppsScriptPost('create_recipe', payload)`. If `!data.ok`, return `res.status(422).json({ error: data.message || data.error || 'Create failed' })`. Otherwise bust cache via `bustRecipeCache(null)`, then `res.status(201).json({ ok: true, recipe_id: data.recipe_id || (data.data && data.data.recipe_id) })`.

5. `router.put('/api/recipes/:id', fn)` -- Extract `payload` from `req.body`, set `payload.recipe_id = req.params.id`. **Activation guardrail (D-02, Pitfall 7):** If `payload.status === 'active'`, check `parseFloat(payload.locked_price) > 0` and `(parseInt(payload.ingredient_count, 10) || 0) >= 1`. If either fails, return `res.status(422).json({ error: 'Cannot activate recipe: locked_price must be set and at least one ingredient must exist' })`. Then call `callAppsScriptPost('update_recipe', payload)`. If `!data.ok`, return 422. Otherwise bust cache via `bustRecipeCache(req.params.id)`, return `res.json({ ok: true })`.

6. `router.delete('/api/recipes/:id', fn)` -- Build payload `{ recipe_id: req.params.id }`. Call `callAppsScriptPost('delete_recipe', payload)`. If `!data.ok`, return 422 with error. Otherwise bust cache, return `res.json({ ok: true })`.

**Module export:** `module.exports = router;`

**Important implementation notes:**
- All six routes use the `/api/recipes` prefix in the path (server.js mounts with `app.use('/', ...)`)
- GET requests do NOT require API key (server.js passes GET through)
- POST/PUT/DELETE are protected by the global API key guard in server.js (no per-route guard needed)
- Availability endpoint does NOT cache its result (stock changes frequently per RESEARCH.md anti-patterns)
- Per-recipe detail cache key format: `C.CACHE_KEYS.RECIPES + ':' + recipeId` (e.g., `sv:recipes:SV-R-000001`)
- Error log format: `'[api/recipes] ' + err.message` or `'[api/recipes/' + recipeId + '] ' + err.message`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser -> middleware | Admin sends recipe data with X-API-Key header for writes; GETs are open (public API) |
| middleware -> Apps Script | Server-token auth; middleware controls all Apps Script calls, never trusts client item_ids |
| middleware -> Redis | Internal cache; no untrusted input in cache keys (status/limit/offset are validated as strings/ints) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-04 | Elevation of Privilege | PUT /api/recipes/:id | mitigate | Activation guardrail: middleware rejects status=active when locked_price <= 0 or ingredient_count < 1 with HTTP 422 |
| T-13-05 | Tampering | GET /api/recipes/:id/availability | mitigate | Client sends only recipe_id; middleware fetches ingredient item_ids from Apps Script server-side (API-02) |
| T-13-06 | Spoofing | POST/PUT/DELETE /api/recipes | mitigate | Global X-API-Key guard in server.js at line 231; all non-GET /api/* routes require valid API key |
| T-13-07 | Denial of Service | Apps Script cold start | accept | 15-second axios timeout; log.error on timeout; admin UI shows error toast -- recoverable on retry |
| T-13-08 | Information Disclosure | GET /api/recipes error responses | mitigate | Error responses return generic messages ("Unable to fetch recipes"), never raw Apps Script error details |
</threat_model>
