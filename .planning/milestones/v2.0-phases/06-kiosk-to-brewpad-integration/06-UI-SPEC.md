# Phase 6 — UI Design Contract

> Visual and interaction contract for Phase 6: Kiosk-to-Brewpad Integration.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — vanilla CSS with CSS custom properties |
| Preset | not applicable |
| Component library | none (custom `bp-*` component classes in `css/brewpad.css`) |
| Icon library | emoji + Unicode (inline in HTML strings) — existing BrewPad pattern |
| Font | Body: Lato, 'Helvetica Neue', Arial, sans-serif (var --font-body) / Display: Georgia (var --font-display) |

This phase makes NO design system changes. It extends the existing `css/brewpad.css`
token vocabulary with two new CSS rules:

1. `.bp-status-badge--neutral` — for the "Pending" status badge color
2. `.bp-kiosk-badge` — for the inline "Kiosk" source indicator on list rows

No other CSS files are modified.

**Visual hierarchy note:** This phase introduces no new primary screens or layout regions.
All new elements (Pending badge, Kiosk badge, Zoho Ref row, Pending filter button) slot
into the existing BrewPad layout hierarchy and inherit its established visual priority
structure. No hierarchy decisions are required for this phase.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inner padding vertical |
| sm | 8px | Compact element spacing, badge inner padding horizontal |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Source: existing `css/brewpad.css` root styles — no deviations for this phase.

Exceptions:
- Filter buttons: `min-height: 44px` (touch target minimum — existing pattern from `.bp-filter-btn`)
- Batch cards: `padding: 12px 14px` (existing `.bp-batch-card` — do not change)
- Detail info rows: `padding: 4px 0` (existing `.bp-detail-info-row` — do not change)
- Badge padding: `2px 8px` for `.bp-status-badge`, `1px 6px` for `.bp-badge` (existing patterns)
- Kiosk badge: `2px 6px` — matches `.bp-badge` compact pattern

## Typography

All values are from the existing `css/brewpad.css` declarations. No new type styles
are introduced by this phase.

Maximum 4 sizes, 2 weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (1rem) | 400 | 1.6 |
| Heading / Card name | 15.2px (0.95rem) | 600 | inherited |
| Label / Secondary info | 14px (0.875rem) | 400 | inherited |
| Badge / Status label | 11.5px (0.72rem) | 600 | 1 |

New elements introduced in this phase use the closest existing size:
- "Pending" filter button label: 14px (0.875rem), weight 600 — matches existing `.bp-filter-btn` label size
- "Kiosk" badge text: 11.5px (0.72rem), weight 600 — uses badge size row above
- "Zoho Ref" detail row label: 14px (0.875rem), weight 600 — matches `.bp-detail-info-label`
- "Zoho Ref" detail row value: 14px (0.875rem), weight 400 — matches `.bp-detail-info-row`

## Color

All color values are from existing `css/brewpad.css` `:root` tokens. No new hex values
are introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--cellar-canvas)` = `#e8e2ca` | Page background, list background |
| Secondary (30%) | `var(--cellar-raised)` = `#faf8f2` | Batch cards, detail pane, filter bar, toast backgrounds |
| Accent (10%) | `var(--cellar-green)` = `#4a6f4b` | Active tab indicator, selected batch card border, primary CTA hover |
| Destructive | `var(--batch-danger)` = `#a83232` | Danger buttons, error toasts only |

Accent reserved for:
- Active filter button background (`var(--stain)` = `#370e13`) — existing pattern
- Active tab underline / color (`var(--cellar-green)`)
- Selected batch card border highlight

**New color additions for this phase:**

| Class | Background | Text | Token basis |
|-------|------------|------|-------------|
| `.bp-status-badge--neutral` | `rgba(154, 134, 114, 0.10)` | `var(--ink-secondary)` = `#6b5442` | Warm neutral — no existing `--neutral` token, derived from `--ink-tertiary` `#9a8672` at low opacity. Communicates "needs attention" without alarm (distinct from `--warning` amber). |
| `.bp-kiosk-badge` | `rgba(74, 111, 138, 0.12)` | `var(--batch-info)` = `#4a6f8a` | Matches existing `.bp-badge--transfer` exactly — blue-slate tone signals an external origin (kiosk). Reuses established blue-info semantic. |

Note on "Pending" badge color decision (RESEARCH.md open question resolved):
Using `--neutral` (warm grey) instead of `--warning` (amber). Amber is already assigned to
"Secondary fermentation" stage — sharing it with "Pending" would create semantic collision.
A warm grey communicates "awaiting staff action" without implying urgency.

## Interaction Contracts

### Pending Filter Button

| Property | Value |
|----------|-------|
| Element type | `<button class="bp-filter-btn">` |
| Label | Pending |
| Position in filter bar | After existing status filters, before "All" if present |
| Active state | `.bp-filter-btn--active` (same as all other filter buttons) |
| Touch target | min-height: 44px (inherited from `.bp-filter-btn`) |
| Click behavior | Filters batch list to show only `status === 'pending'` rows |

### Kiosk Badge (list row)

| Property | Value |
|----------|-------|
| Element type | `<span class="bp-kiosk-badge">` |
| Label | Kiosk |
| Position | Immediately after the status badge in the card header / list row header |
| Visibility condition | `b.source === 'kiosk' && statusKey === 'pending'` — disappears when batch goes active |
| Interactive | No — display only, no click handler |

### Pending Status Badge (list row)

| Property | Value |
|----------|-------|
| Element type | `<span class="bp-status-badge bp-status-badge--neutral">` |
| Label | Pending |
| Position | Same position as all other status badges in batch cards |
| Interactive | No (same as other status badges in list view) |

### Zoho Ref Row (detail view)

| Property | Value |
|----------|-------|
| Element type | `<div class="bp-detail-info-row">` |
| Label cell | `<span class="bp-detail-info-label">Zoho Ref</span>` |
| Value cell | `<span>{escapeHTML(b.zoho_so_number)}</span>` |
| Position | Last row in the `.bp-detail-info` grid (after Customer, Product, Batch ID) |
| Visibility condition | Only rendered when `b.zoho_so_number` is truthy |
| Interactive | No — text only; Zoho link is out of scope for this phase |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (staff action on pending batch) | "Set Up Batch" — verb + noun, appears as the main action button in pending batch detail view |
| Pending filter button label | "Pending" |
| Kiosk badge label | "Kiosk" |
| Zoho Ref detail label | "Zoho Ref" |
| "Pending" status badge label | "Pending" |
| Empty state heading (no pending batches) | "No pending batches" |
| Empty state body (no pending batches) | "Kiosk sales with Maker's Fee will appear here automatically." |
| Error state — batch creation failure (staff-facing, via toast) | "Batch could not be created automatically — it has been queued for retry." |
| Error state — retry exhausted (log-level, not UI) | Not surfaced to staff UI in this phase — ops alert via `log.error` only |
| Walk-in customer placeholder | "Walk-in Customer" — appears as customer name when kiosk sale has no named contact |

No destructive actions are introduced in this phase. The "Set Up Batch" flow (assigning
a schedule to a pending batch) is an update, not a deletion. No confirmation dialog required.

Source: CONTEXT.md decisions D-06, D-07, D-11, D-12 + Pitfall 6 in RESEARCH.md.

## State Inventory

New states introduced by this phase:

| State | Trigger | Visual Treatment |
|-------|---------|-----------------|
| `status: pending` | Batch auto-created from kiosk sale with no schedule | `.bp-status-badge--neutral` label "Pending" |
| `source: kiosk` + `status: pending` | Same trigger | `.bp-kiosk-badge` label "Kiosk" alongside status badge |
| `source: kiosk` + `status !== pending` | Staff assigns schedule, batch goes active | Kiosk badge disappears; normal status badge shown |
| `zoho_so_number` present | Any batch with a linked SO | "Zoho Ref" row appears in detail info grid |
| `zoho_so_number` absent | Manually-created batches | "Zoho Ref" row is omitted from detail info grid |
