<objective>
Implement the frontend payment state machine that prevents duplicate charges.

Purpose: Customers were getting charged multiple times because stale Helcim state (_helcimCheckoutToken, _helcimTransactionId) was never cleared on error paths, allowing the iframe to re-open and charge again. This plan adds a cooldown lock, clears all state on every error path, and generates client-side idempotency keys.

Output: Modified 12-checkout.js with bulletproof payment state, plus unit tests proving safety behaviors.
</objective>
