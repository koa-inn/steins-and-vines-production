## 🔴 START HERE — Live production bug (kiosk products blank after first sale)

**Symptom:** after the first sale, the kiosk product grid goes blank (and stays blank until a full page reload).

**Root cause (fully diagnosed):**
1. After a sale, the kiosk force-refreshes via `kioskLoadProducts(true)` → `GET /api/kiosk/products?bust=1`, sent under the **device token**.
2. The `?bust=1` branch (M7, Phase 52-05, `zoho-middleware/routes/catalog.js:808`) only allowed `['legacy','session']` → the device token gets **403**. This began with the **Phase 46 auth cutover (2026-07-08)** when the kiosk moved from `x-api-key` to the device token.
3. **Frontend gap:** `js/kiosk-core.js` `kioskLoadProducts()` (~lines 789–802) does `.then(r => r.json())` **without checking `r.ok`**. On the 403 it sets `_kioskProducts = data.items || []` → `[]` → **blanks the grid** and sets `_kioskProductsLoaded = true` so it stays blank until reload.

**Affects the REAL production kiosk** (prod frontend also does bust=1 → prod middleware 403) **and staging** (staging calls the prod middleware).

**Two-part fix:**
- **(a) Backend — DONE (commit `0d9fe73`):** `catalog.js:808` now allows `'device'`. **BUT this is a MIDDLEWARE change and the middleware only runs on the PROD Railway instance (deployed from the production repo) — there is NO staging middleware.** So it does NOT take effect until the **prod middleware redeploys**. → **Expedite `0d9fe73` to the prod middleware as its own small deploy** (isolated, low-risk); the live store kiosk is degraded now.
- **(b) Frontend — NOT YET DONE (do this on resume):** in `js/kiosk-core.js` `kioskLoadProducts()`, check `r.ok`/`r.status` before `r.json()`; on failure **do not** wipe `_kioskProducts` and **do not** set `_kioskProductsLoaded = true` (keep showing current products + a soft error). Apply the same guard to `kioskLoadRecipes()` (~line 817, same shape). Add a regression test. Belt-and-suspenders so a denied/failed refresh never blanks the grid.

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Assuming a middleware fix is "live" once pushed to staging | The middleware runs only on prod Railway (from the production repo); staging has none. A `git push origin main` does NOT deploy middleware. | advisory | For any `zoho-middleware/**` change, state explicitly that it takes effect only on a prod middleware deploy; don't tell the owner it's fixed on staging. |
| `fetch().then(r => r.json())` without checking `r.ok` | Blanks the product grid on a 403/500 by treating the error body as an empty item list, then marks loaded=true. | advisory | Always check `r.ok` before consuming a body; on failure preserve prior state rather than overwriting with empties. |
| Build-stamp churn in commits | `npm run build` re-stamps ~19 unrelated HTML files (cache-bust `?v=`) + admin bundles. | advisory | After build, `git restore` the unrelated stamped files; commit only the files relevant to the change (keep the changed page's stamp so its bundle cache-busts). |
