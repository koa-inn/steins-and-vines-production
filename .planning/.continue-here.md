## 2. Production incident — BrewPad staff auth (FIXED)
- **Symptom:** BrewPad customer lookup returned nothing (403); later bottling-invite too.
- **Root cause (confirmed via a temp server diagnostic):** BrewPad/admin are served from
  steinsandvines.ca but call the middleware on a different site (Railway), so the httpOnly
  `sv_session` cookie is a cross-site cookie that modern browsers drop — every API request
  arrived with NO cookie (`hasCookieHeader=false`). NOT Zoho, NOT Redis, NOT the kiosk deploy.
- **Fix shipped (commit `6a7b0ddd`, live):** header-token auth. Login (`POST /auth/google`)
  now also returns the session id in the body; `authTiers.resolveTier` + `requireTiers`
  accept it via an `x-session-token` header; brewpad.js/admin.js store it (localStorage) and
  attach it on MIDDLEWARE_URL requests via a browser-only fetch wrapper (skipped under jest).
  Backward-compatible (cookie path untouched). Kiosk (device token) + money path untouched.
  Tests: auth-tiers-guard +3, auth-google-route updated. FE 1019 / MW 1304 green.
- Verified working by owner: customer lookup ✅, bottling invite ✅.
- We first attempted an `api.steinsandvines.ca` first-party subdomain but ABANDONED it:
  Railway could not issue that domain's TLS cert (stuck 9+ hrs at VALIDATING_OWNERSHIP,
