<objective>
Fix the mark-bottled staleness (owner ticket #2): completing the Bottling/Packaging task on a batch
must remove it from the Ready-to-Bottle list immediately, with no full page reload.

The root cause is 100% client-side (confirmed by 69-PATTERNS.md, correcting 69-CONTEXT.md's earlier
server claim): the server already busts the `gbds` cache on every `bulk_update_batch_tasks` write, but
the client's task-checkbox handlers re-render the stale in-memory `_dashSummary` (via `renderDashboard()`
/ `renderTasks()`) instead of refetching it. Fix: after a successful task write, force a dashboard
refetch by applying the already-proven `afterBatchWrite(id, { listAffecting: true }); loadDashboard();`
pairing (precedent js/brewpad.js:6670-6672 / 6682-6683) to all THREE task-checkbox handlers.

Purpose: staff see the true bottling state the moment they check the task — no confusing reload.
Output: updated js/brewpad.js (+ rebuilt js/brewpad.min.js), new regression test file.

NO apps-script/adminApi.gs change — the server cache is already correct. No owner Apps Script redeploy.
</objective>
