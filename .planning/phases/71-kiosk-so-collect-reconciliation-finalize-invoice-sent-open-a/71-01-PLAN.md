<objective>
Fix the kiosk "collect payment on an existing sales order" money-path so a charged SO collection reconciles in Zoho exactly like the normal POS `processSale` end-state: a finalized (open/sent) invoice that ends **paid**, with the customerpayment **applied to the invoice** (not left as an unapplied advance against the sales order).

Root cause (`webhooks.js:206`): the collect APPROVED path books the customerpayment with `salesorders_to_apply`, which Zoho does not reconcile against any bookable invoice; it also never finalizes the invoice and swallows post-charge failures with a bare `log.warn`. Confirmed live: SO-000076 → INV-000169 stuck `draft` $649.74, Payment #170 an unapplied advance (`unused_amount: 649.74`), Helcim txn 53184102 charged fine.

Purpose: no orphaned charge — every collected dollar books to a paid invoice, and any post-charge failure is recoverable (money-path doctrine, phases 45/49/68).
Output: `webhooks.js` collect block rewritten to convert-or-reuse → submit → apply-to-invoice-id, fail-closed; a shared finalize helper in `money-path.js`; a collect reconcile-failure sentinel in `reconcile.js`; a new constant; and a full test harness.

Note for executor (out of scope, flag only — do NOT fix here): the DECLINED branch at `webhooks.js:227` reads `ctx.idempotencyKey` but `collect.js:105` stores `idempotency_key`, and the idem cache key is keyed by `soId` not the generated value — a latent cleanup bug on the DECLINED path. Surface it in your SUMMARY; do not expand this plan to fix it.
</objective>
