<objective>
Add a "Phone order / card not present" (MOTO) tender to the kiosk. The card is keyed ONLY into Helcim's hosted HelcimPay.js iframe (PAN never touches our DOM/server — PCI SAQ-A). The server initializes the HelcimPay session in-process, and — before booking anything — VERIFIES the Helcim captured amount covers the invoice total (Phase 49 `getCardTransactionById` readback, ±$0.01). The rest of the kiosk pipeline (stock, batch, invoice, gift-card split) is unchanged; only the payment leg swaps terminal → HelcimPay.

Purpose: Let staff take a phone-order card payment on the kiosk without dragging us into PCI SAQ A-EP scope and without ever booking phantom revenue.
Output: A `tender:'moto'` branch on the existing `/api/kiosk/sale` → `/confirm` pipeline (extend, don't fork), a kiosk phone-order button + iframe mount, and kiosk.html's first scoped CSP.

WARNING — deploy ordering: the CSP added here is static-analysis-derived (RESEARCH Assumption A1) and MUST be live-verified on staging (Plan 70-03) before any production force-push. A missing CSP domain silently breaks a kiosk feature exactly like the 2026-07-22 Meta-pixel incident.
</objective>
