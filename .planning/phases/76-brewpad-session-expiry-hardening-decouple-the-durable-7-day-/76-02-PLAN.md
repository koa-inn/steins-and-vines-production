<objective>
Build the single allow-listed Apps-Script proxy the whole migration depends on: `POST /api/batch/admin-proxy` in `zoho-middleware/routes/pos.js`, gated by `authTiers.requireTiers(['legacy','session'])` (device tier excluded — BrewPad is session-scoped), which checks the request `action` against a hardcoded allow-list and forwards `{action, ...params, server_token}` to Apps Script using the exact `stampBottlingInviteSent` axios shape. Simultaneously close the sliding-expiry gap (RESEARCH.md Pitfall 2): wire the already-written-but-uncalled `session.touchSession(sid)` into `authTiers.resolveTier()` so `sv_session`'s Redis TTL actually slides once Google's masking is removed.

Purpose: This route is the security boundary and the transport for BrewPad's single-credential end state. The allow-list (never a free-form `action` passthrough) and the token-strip are the two mitigations that stop this from re-introducing the dual-credential surface the phase deletes.
Output: A tested proxy route + touchSession wiring, both covered by a new middleware test file, with the full frontend+middleware suites green (CLAUDE.md: touching `lib/authTiers.js` requires BOTH suites).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → middleware | `x-session-token` (or `sv_session` cookie) is the sole admin-grade identity; untrusted client input (incl. any `token` body field) crosses here. |
| middleware → Apps Script | `server_token` forwarded server-side; the client never sees or controls it. |

NEVER a free-form `req.body.action` passthrough. Tested (Task 1 Test 2). |
| T-76-02-02 | Spoofing | client-supplied Google `token` body field | mitigate | `delete payload.token` before forward; identity is proven solely by `requireTiers(['legacy','session'])` (a valid x-session-token already binds to an allowlisted staff email at /auth/google mint — RESEARCH.md verified). | T-76-02-03 | Information Disclosure | unauthenticated read of batch/PII data via the proxy | mitigate | `requireTiers` rejects no-credential (401) and device-only (wrong tier) BEFORE any Apps Script call. Tested (Task 1 Tests 3 & 5). |
