<objective>
Extend `apps-script/adminApi.gs`'s `doPost` `server_token` allowlist so the Railway middleware can invoke BrewPad's 9 batch/task/reading/schedule WRITE actions server-side (with `APPS_SCRIPT_SERVER_TOKEN` / script-property `SERVER_WRITE_TOKEN`), then get the owner to redeploy and live-verify. This is the long-lead, write-path-enabling prerequisite for the whole migration: per RESEARCH.md Pitfall 1, `doPost`'s server_token branch is a CLOSED `if`-chain (not a generic passthrough like `doGet`), so these actions currently return `invalid_action` under server_token — exactly the latent bug `stampBottlingInviteSent` (`pos.js:3697`) has been silently hitting.

Purpose: The middleware proxy (Plan 76-02) cannot reach BrewPad writes until this `.gs` change is redeployed and verified live. The redeploy is a manual owner step outside CI (STATE.md anti-pattern: "green tests ≠ working system" — Apps-Script changes have no CI/Jest and must be exercised against the live system).
Output: Edited `adminApi.gs` + a confirmed owner redeploy + a live probe proving both the new write reachability and RESEARCH.md Assumption A2 (reads already work under server_token, no `.gs` change needed for reads).
</objective>
