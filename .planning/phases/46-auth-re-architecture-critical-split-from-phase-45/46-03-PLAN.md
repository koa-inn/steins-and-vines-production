<objective>
Restructure the single-branch `/api` key guard in `server.js` into a **three-tier credential dispatcher** (legacy key / kiosk device token / session cookie), all valid simultaneously during the dual-accept window (D-46-11). Introduce `lib/authTiers.js` holding the explicit kiosk-scoped route allowlist and the dispatch logic, mount `cookie-parser`, add the keyless exemptions for the three public POSTs (D-46-10 / Finding #1), and extend `requirePiiApiKey` (PII GET routes) to accept a session — while ensuring the device token can NEVER reach admin-grade routes (D-46-02).

Purpose: This is the keystone that lets each surface migrate independently behind one server-side gate, and is what "ends the window" the moment the owner rotates `API_SECRET_KEY` (the legacy branch simply stops matching). The guard attaches `req.authTier` so downstream in-route checks (migrated in 46-04) consult one source of truth instead of re-validating headers.
Output: `lib/authTiers.js`, modified `server.js`, integration tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api guard | Three credential types cross; misclassification = privilege boundary failure |
| stolen iPad (device token) → admin routes | Must be blocked at the guard |
| cross-site browser → session routes | CSRF surface given SameSite=None cookies |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46-03 | Spoofing | stolen-iPad device token | mitigate | explicit kiosk route allowlist; `allowAdmin('device')===false`; device rejected on `!isKioskRoute` and PII routes (D-46-02) |
| T-46-04 | Tampering (CSRF) | session-cookie routes with SameSite=None | mitigate | `requireAllowedReferer` still runs on session-tier routes (NOT added to the exemption list) — the actual CSRF control |
| T-46-06 | Information Disclosure | keyless /bookings /contacts (referer-only) | accept | matches existing /promo/validate risk profile exactly (Finding #1); no new risk class; recorded in audit trail (46-RESEARCH.md Open-Q #2) |
| T-46-07 | Elevation of Privilege | path-prefix over-scoping | mitigate | explicit KIOSK_ROUTES list, not `/api/kiosk/*` prefix (anti-pattern warning) |
| T-46-11 | Repudiation | legacy key surviving past rotation | mitigate | legacy branch dies when API_SECRET_KEY value rotates (46-10); canary logging optional in 46-10 |
| T-46-17 | Elevation of Privilege | guard fails open if resolveTier throws | mitigate | async guard catch → 403 (fail closed); null tier → 403 |
