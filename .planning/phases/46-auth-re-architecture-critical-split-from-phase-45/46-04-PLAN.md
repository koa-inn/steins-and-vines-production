<objective>
Migrate the **13 in-route `apiKeyGuard.matches(req.headers['x-api-key'])` checks in `routes/pos.js`** (plus `consignment.js` and `catalog.js`) so they consult the `req.authTier` the 46-03 guard now attaches, rather than independently re-requiring the legacy key. Without this, the kiosk breaks the moment `API_SECRET_KEY` is rotated (46-10): the global guard would admit a device-token request but these in-route checks would 403 it because they only recognise the old key.

Purpose: Close the second, easily-missed enforcement layer (Pitfall: "remove key = one-line fix"). Kiosk-scoped pos routes must accept any authenticated tier; the admin-grade ones (`/api/kiosk/gift-card/void`, consignment) must still reject a device token.
Output: modified pos.js/consignment.js/catalog.js in-route checks, plus a test proving device-token acceptance on kiosk routes and rejection on the void route.
</objective>
