## Interaction Contracts

### List → Detail Swap (D-01)

- Clicking any recipe table row calls `openRecipeDetail(recipeId)`
- `#recipes-list-view` gets `display:none`; `#recipes-detail-view` gets `display:block`
- Back button (`#recipes-back-btn`) reverses the swap and re-renders the list (no full reload — uses `_recipesState.list`)
- No modal. No new page load.

### Ingredient Autocomplete (D-03, D-04)

- Catalog pre-loaded from `GET /api/catalog/ingredients` on tab open (once per tab session)
- Typing into `ing-search` input filters `_recipesState.catalog` client-side (no API call per keystroke)
- Dropdown shows max 6 results; each result row: `{item_name} — {sku} ({stock_on_hand} {unit} available)`
- Selecting a result: populates `ing-qty` step to match unit type, sets `ing-unit` text, sets `ing-stock-hint` text, stores `item_id` in row dataset
- If catalog not yet loaded, show "Loading ingredient catalog..." placeholder in dropdown and disable add-ingredient button

### Availability Indicators (D-06, D-07, D-08)

- Availability checked automatically on `openRecipeDetail()` — no manual "Check Stock" button
- Each ingredient row shows colored dot via `ing-status-dot`: green (batches >= 3), yellow (batches 1–2), red (batches = 0)
- Banner updates after availability response arrives; during load shows "Checking stock..." loading state
- If availability returns `status: 'unknown'` for an ingredient (cold cache), dot shows grey with title "Stock data loading — try again shortly"

### Activation Guardrail (D-02)

- Status field is a `<select>` with options: draft, active, inactive
- When user changes status select to "active": JavaScript runs `canActivateRecipe(recipe, ingredients)`:
  - If `locked_price` is empty or 0: revert select to previous value, show inline error "Set a locked price before activating"
  - If ingredient count is 0: revert select to previous value, show inline error "Add at least one ingredient before activating"
- Visual treatment: inline error text in `--batch-danger` color below the status select field, disappears on next field interaction

### Destructive Actions

- Delete Recipe: confirmation via `window.confirm("Delete recipe '{name}'? This cannot be undone.")`. If confirmed, `DELETE /api/recipes/:id`. On success: swap back to list view, refresh list, show toast "Recipe deleted."
- Deactivate (status change to "inactive" from "active"): no confirmation dialog required — reversible action
- Delete is only shown in detail view, never in the list view table

## Interaction States to Implement

This section ensures the executor covers all required states without ambiguity.

| View | State | Treatment |
|------|-------|-----------|
| List | Loading | Show "Loading recipes..." text in tbody, no spinner |
| List | Loaded, rows present | Render `admin-table` rows |
| List | Empty (no recipes) | Hide table, show `#recipes-empty` paragraph |
| List | Empty (filter mismatch) | Hide table, show filter-mismatch empty message |
| List | Load error | Show error empty message with retry link |
| Detail | Loading recipe + availability | Show "Loading..." in detail area; availability banner shows "Checking stock..." |
| Detail | Loaded | Form pre-populated, availability banner set, ingredient rows rendered |
| Detail | Edit mode (unsaved changes) | No explicit "edit mode" — form is always editable. Save button always visible. |
| Detail | Saving | Save button disabled + text changes to "Saving..." |
| Detail | Save success | Toast "Recipe saved.", form re-loads saved values |
| Detail | Save error | Toast "Could not save recipe. Please try again." Save button re-enabled. |
| Detail | Status=active guardrail blocked | Inline error below status select |
| Ingredient row | Unselected (new row) | Search input focused, placeholder visible |
| Ingredient row | Autocomplete open | Dropdown below input, up to 6 results |
| Ingredient row | Item selected | Unit, hint, and availability dot populated |
| Ingredient row | Stock ok | Green dot (--batch-success) |
| Ingredient row | Stock low | Yellow dot (--batch-warning) |
| Ingredient row | Stock out | Red dot (--batch-danger) |

## Accessibility Contracts

Following existing admin panel patterns and WCAG 2.1 AA:

- All form fields have `<label>` elements associated via `for`/`id`
- Autocomplete dropdown uses `role="listbox"` + `role="option"` on results
- Status select change that triggers guardrail error: error message rendered in `<span>` with `role="alert"` so screen readers announce it
- Availability banner has `aria-live="polite"` to announce stock status updates after load
- Delete confirm uses native `window.confirm()` — accessible by default
- Ingredient remove button has `aria-label="Remove {item_name}"` populated dynamically
- Focus-visible outline: inherits `outline: 2px solid var(--color-burgundy); outline-offset: 2px` from global styles
- Minimum touch target 44px height on all buttons (enforced by `.btn` / `.btn-secondary` `min-height: 44px`)
