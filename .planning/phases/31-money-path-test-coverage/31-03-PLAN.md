lib/helcim.js#verifyWebhookSignature(webhookId, timestamp, rawBody, signature):
- payload = webhookId + '.' + timestamp + '.' + rawBody
- key candidates tried: Buffer.from(rawSecret,'base64'), then rawSecret as utf8 string
- signature candidates split on ' ', any "prefix," stripped (e.g. 'v1,abc' → 'abc')
- returns true if any (key, candidate) matches via crypto.timingSafeEqual
- FAILS OPEN (returns true) when HELCIM_WEBHOOK_SECRET is not set — current behavior; the gap Phase 32 (HARDEN-02) closes

routes/webhooks.js (confirmed):
- line 30: router.post(['/api/webhooks/terminal','/webhooks/terminal'], handler)
- reads headers webhook-id, webhook-timestamp, webhook-signature
- calls helcimLib.verifyWebhookSignature(...); on false → res.status(401).json({error:'Invalid signature'})
- on true → res.status(200).json({received:true})
- /webhooks/ prefix is API-key-exempt in server.js (line 260) — no x-api-key header needed

Valid-sig helper (from 31-PATTERNS.md): makeValidSig strips a whsec_ prefix, base64-decodes the secret to a key, HMAC-SHA256 over webhookId.timestamp.rawBody, base64-digest.
