# Phase 27.1 Plan 02: Add Inline Delete to BrewPad Needs Scheduling Rows Summary

## One-liner

Inline Delete button on BrewPad dashboard Needs Scheduling rows using showConfirmSheet danger bottom-sheet + existing delete_batch action, wired via event delegation, with confirm copy showing batch ID + product + customer and refreshing the dashboard without page reload.

## What Was Built

Added an inline Delete button to each Needs Scheduling row on the BrewPad dashboard (`js/brewpad.js`). Staff can now delete duplicate pending batches from the BrewPad surface instead of editing the Batches Google Sheet by hand. This mirrors Plan 27.1-01 (admin surface) on the BrewPad surface where pending batches also appear as "Needs Scheduling" rows.

### Changes Made

**`js/brewpad.js`** — two surgical edits:

1. **Button markup** (`pend.forEach` loop, ~line 1052–1056): After closing `.bp-task-body`, before closing `.bp-task-row`, appended:
   ```javascript
   html += '<button type="button" class="btn-secondary bp-btn-sm bp-danger-btn bp-needsched-delete-btn"'
     + ' data-batch-id="' + escapeHTML(it.batch_id || '') + '"'
     + ' data-product="' + escapeHTML(it.product_name || '') + '"'
     + ' data-customer="' + escapeHTML(it.customer_name || '') + '">Delete</button>';
   ```
   Data attributes carry `escapeHTML`-encoded product and customer names for the confirm copy (T-27.1-07 XSS mitigation). The `.bp-task-body` close tag is now a separate `html += '</div>'` so the Delete button sits as a sibling of `.bp-task-body` within `.bp-task-row`.

2. **Delegated handler** (`initDelegation` dashInner click block, placed before `bp-batch-chip` branch): New `e.target.closest('.bp-needsched-delete-btn')` branch. On click: reads `data-batch-id`/`data-product`/`data-customer`, calls `showConfirmSheet` with the D-09 danger message, `'Delete'` label, `'bp-confirm-btn--danger'` class. In `onOk` callback: disables button, calls `adminApiPost('delete_batch', { batch_id: bid })`. On `.then`: shows success toast, resets `_batchesLoaded = false; _allBatchesData = []; _eagerLoadTime = 0; _dashLoadTime = 0;`, calls `loadBatches()`. On `.catch(err)`: shows error toast and re-enables button. Does NOT call `closeBatchDetail()` (no detail pane open from this handler). Ends with `return;` so it does not fall through to the chip open-batch branch.

**`js/brewpad.min.js`, `js/main.min.js`, and all HTML pages** — regenerated by `npm run build`.
