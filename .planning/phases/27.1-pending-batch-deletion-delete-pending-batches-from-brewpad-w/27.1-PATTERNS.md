## Shared Patterns

### API call — `adminApiPost`
**Apply to:** both new inline Delete handlers
```javascript
adminApiPost('delete_batch', { batch_id: bid })
  .then(function () { /* success */ })
  .catch(function (err) { showToast('Failed: ' + err.message, 'error'); });
```
The backend returns `{ ok: false, error: 'not_found' }` for an already-deleted batch — the `.catch` path handles this (the Promise rejects on non-ok responses in the existing `adminApiPost` wrapper).

### Confirm dialog copy — D-09/D-10 template
```
Delete SV-B-XXXXXX (Product Name — Customer Name)? Any attached tasks will be removed. This cannot be undone.
```
`em dash` = `—` in JS string; omit `— Customer Name` segment if `customer_name` is blank.

### Button disable on confirm / re-enable on error
```javascript
btn.disabled = true;
adminApiPost(...)
  .then(function () { /* row will disappear — no re-enable needed */ })
  .catch(function (err) {
    showToast('Failed: ' + err.message, 'error');
    btn.disabled = false;
  });
```

### Event propagation stop — inline buttons inside clickable rows
```javascript
btn.addEventListener('click', function (e) {
  e.stopPropagation(); // prevents row-open handler from firing
  ...
});
```
Admin additionally requires a `.classList.contains('batch-inline-delete-btn') return;` guard in the row-click handler (same pattern as lines 5698–5700).

- Use `var`, not `let`/`const`. Use string concatenation, not template literals.
