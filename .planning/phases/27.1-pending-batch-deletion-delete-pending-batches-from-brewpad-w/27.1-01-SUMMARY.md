# Phase 27.1 Plan 01: Add Inline Delete to Admin Pending Batch Rows Summary

## One-liner

Inline Delete button on admin pending batch rows using showConfirm + existing delete_batch action, with confirm copy showing batch ID + product + customer and refreshing list without page reload.

## What Was Built

Added an inline Delete button beside the Activate / Schedule & activate buttons on pending rows in the admin Batches list (`js/admin.js`). Staff can now delete duplicate pending batches directly from the list view instead of editing the Batches Google Sheet by hand.

### Changes Made

**`js/admin.js`** — three surgical edits:

1. **Button markup** (line 5688): Inside the existing `if (String(b.status).toLowerCase() === 'pending')` block, after `batch-schedule-activate-btn`, appended:
   ```javascript
   actionCell += '<button type="button" class="btn-secondary admin-btn-sm admin-btn-danger batch-inline-delete-btn" data-batch-id="..." data-product="..." data-customer="...">Delete</button>';
   ```
   Data attributes carry `escapeHTML`-encoded product and customer names for the confirm copy (T-27.1-04 XSS mitigation).

2. **Row-click guard** (line 5702): Added `if (e.target.classList.contains('batch-inline-delete-btn')) return;` to the existing propagation guard block so clicking Delete does not also open the detail modal.

3. **Delegated handler** (lines 5773–5798): New `tbody.querySelectorAll('.batch-inline-delete-btn').forEach(...)` block modeled exactly on the inline Activate handler pattern. On confirm: disables button, calls `adminApiPost('delete_batch', { batch_id: bid })`, on success shows toast and runs `vesselsData = null; loadBatchesData(); loadBatchDashboardSummary()`. On error: shows error toast and re-enables button.

**`js/admin.min.js`, `js/main.min.js`** — regenerated by `npm run build`.
