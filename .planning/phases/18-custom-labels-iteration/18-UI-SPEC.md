## Spacing Scale

Existing project uses `rem`-based spacing without named tokens. The 8-point grid maps to the rem scale at 16px base:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (0.25rem) | Icon gaps, border offsets, inline nudges |
| sm | 8px (0.5rem) | Preview column gap, canvas border-radius inner padding |
| md | 16px (1rem) | Default element spacing, table cell padding |
| lg | 24px (1.5rem) | Preview column flex gap, controls row gap |
| xl | 32px (2rem) | Steps grid gap, mockup controls margin-bottom |
| 2xl | 48px (3rem) | Mobile hero padding, section vertical padding |
| 3xl | 64px (4rem) | Desktop section padding (existing pattern: `padding: 4rem 0`) |

Exceptions:
- Touch targets (upload label, reset button): minimum 44px height enforced — `.labels-reset-btn { min-height: 44px }` already present in `labels.css`.
- Preview canvas columns: `max-width: 280px` per column at desktop, `max-width: 320px` at mobile (inherits block width). Not a spacing unit — a layout constraint.
- Step number circles: 48px diameter — existing `.labels-step-number { width: 48px; height: 48px }`.

## Visual Hierarchy

**Primary focal point: the 3-canvas preview panel.**

The three side-by-side canvases (Flat View / On a Can / On a Bottle) are the dominant visual element of this page and must be the first thing the eye lands on after the hero headline. Design decisions that reinforce this:

- The `.labels-previews` flex container occupies the full content width with no competing visual elements alongside it.
- Upload controls sit above the canvases with reduced visual weight (secondary button style) so they read as inputs to the focal panel, not competitors.
- Section background contrast (`.labels-mockup` section uses the dominant cream, not the secondary off-white) keeps the canvas area visually isolated.
- On mobile, the stacked canvases retain their role as the page's visual anchor — the upload control collapses above them, not between them.

Secondary focal point: the pricing table. Tertiary: the design guidelines cards.

## Interaction Contract

### 3-Preview Mockup Tool (D-01 through D-06)

**Default state (no upload):**
- All 3 canvases display placeholder composited from `images/labels/placeholder-label.svg`
- Placeholder text: "Your Design Here" (existing placeholder SVG carries this)
- Reset button: `disabled` attribute set, opacity 0.5, cursor not-allowed
- Upload button: fully enabled

**After upload:**
- FileReader reads the file; `Image` object loaded
- All 3 canvases update simultaneously in a single render pass
- Reset button becomes enabled (`disabled` attribute removed)
- Error state if file is invalid type or exceeds 5 MB (see Copywriting Contract)

**Label-type change:**
- Fires on `<select>` `change` event
- Re-renders all 3 canvases (re-reads current image or placeholder)
- Toggles `hidden` class on `#preview-can-wrap` and `#preview-bottle-wrap` based on selected label's `containers` field
- Flat view always visible regardless of `containers` value

**Container compatibility show/hide (D-06):**
- `containers: 'both'` — all 3 previews visible
- `containers: 'bottle'` — can preview hidden; flat + bottle visible
- `containers: 'can'` — bottle preview hidden; flat + can visible
- When only 2 previews are visible, the remaining 2 columns each expand to fill the row (flexbox natural stretch — no explicit width override needed)

**Flat preview (D-03):**
- Canvas renders label image in a centered rectangle at the label's actual aspect ratio (width:height from `LABEL_DATA`)
- Dimension text `W" x H"` rendered below the rectangle in canvas (font: `14px Lato, Arial, sans-serif`)
- For circle labels: dimension text reads `D" circle`
- Thin border: `1px solid rgba(0,0,0,0.2)` around the label rectangle

**Can/bottle preview (D-04):**
- Scanline cylindrical warp: 40 horizontal slices, cosine-scaled widths
- Cosine scale factor: `cos(t) * 0.3 + 0.7` where t maps slice position to -PI/2..PI/2
- Label region coordinates defined empirically after photo download (see Assumptions)
- Photo loaded as background image on canvas; label warped on top within label region
- SVG fallback: if photo fails to load, `drawFallbackTemplate()` renders the existing SVG can/bottle shape

**Upload validation (security + UX):**
- Accepted MIME types: `image/png`, `image/jpeg`, `image/webp` — no `image/svg+xml`
- Max file size: 5 MB
- On invalid file: show inline error message below upload controls (see Copywriting Contract)
- Validation fires before FileReader; no file is ever read if validation fails

**Transitions:**
- No animated canvas transitions — immediate re-render on all state changes
- Button state changes (enabled/disabled) are immediate

### Pricing Table

- Rendered on `DOMContentLoaded` via `buildPricingTable()`
- Grouped into 3 sections: BOPP, Poly, Paper (D-13)
- Each group: `<h3>` group title + `<p>` subtitle + `<table>`
- No interactive elements — static data display
- Continuous roll label (4x100) included in BOPP group with "price per inch" in size cell

### Responsive Behavior

| Breakpoint | Layout |
|------------|--------|
| > 768px | 3-column preview (flat + can + bottle) side by side; flex row |
| ≤ 768px | Single column; canvases stacked vertically; each canvas `max-width: 320px; width: 100%` |
| ≤ 768px | Pricing table: reduced cell padding (0.5rem 0.75rem), font-size 0.9rem |

The 768px breakpoint matches the existing `css/labels.css` mobile breakpoint — no new breakpoints added.

## Accessibility

Inherits existing site accessibility patterns from `css/styles.css`:
- Focus ring: `outline: 2px solid var(--color-burgundy); outline-offset: 2px` on `:focus-visible`
- Skip-to-content link already present in `custom-labels.html`
- All interactive elements must be keyboard-operable

Phase-specific requirements:
- `<select>` label-type dropdown: wrap in `<label>` with visible text "Label size:"
- Upload `<label for="labels-upload">` already provides accessible name for hidden file input — preserve
- Reset `<button>` has text content "Reset Preview" — no additional labelling needed
- Canvas elements: add `aria-label` to each canvas describing its purpose (e.g., `aria-label="Flat label preview"`)
- Preview column labels (`.labels-preview-label`) are decorative — no landmark role needed
- Error messages: rendered as `role="alert"` or `aria-live="polite"` so screen readers announce them
