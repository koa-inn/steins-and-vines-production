<!-- Contract for the new module. Plan 83-14 and the tests depend on exactly these names. -->

Module: zoho-middleware/scripts/migration-allowlist.js (CommonJS, ES5-style `var`/`function` like migration-guard.js, 'use strict')
  ready(): Promise<void>
      Wraps libpg-query's loadModule(). Idempotent: caches and returns the same promise on repeated calls.
  checkSql(fileText: string): Array<{ statement: string, rule: string }>
      Synchronous. Throws Error('migration-allowlist: call ready() first') if ready() has not resolved.
      It must NOT turn a "not initialised" condition into a parse-error violation.
      Returns [] when the Up section is clean.
  checkMigrationsDir(dir: string): Array<{ file: string, statement: string, rule: string }>
      Runs checkSql over every regular file / symlink in dir (withFileTypes; isFile() || isSymbolicLink()) whose name matches /\.sql$/i and is not a dotfile. Sorted by file name.
  findUnguardedFiles(dir: string): Array<{ file: string, statement: string, rule: 'non-sql-file' }>
      Same dirent filter (isFile() || isSymbolicLink(), non-dotfile), and every entry that does not match /\.sql$/i is a violation.
      Directories are ignored (REVIEW IN-02 fix: node-pg-migrate only loads files and symlinks).

Rule names (stable strings, used in tests, CLI stderr and the 83-14 README):
  missing-up-marker | backslash | parse-error | statement-not-allowed | alter-not-allowed |
  enum-rename | insert-shape | node-not-allowed | function-not-allowed | schema-not-public |
  unreadable-file | non-sql-file

CLI: node scripts/migration-allowlist.js [dir]   (default dir: path.join(__dirname, '..', 'migrations'))
  success: exit 0, stdout exactly "migration-allowlist: N file(s) additive-only OK" (N = non-dotfile file/symlink count)
  failure: exit 1, one "file: rule: statement" line per violation on stderr, then a summary line
           "migration-allowlist: K violation(s) found — deploy-time migrations must be additive only (D-04). Use migrations-manual/."
  internal error (WASM load failure, unreadable dir): exit 1 with "migration-allowlist: " + message on stderr

libpg-query@16.7.3 API (verified in research): `loadModule(): Promise<void>`, `parseSync(sql): { version, stmts: [{ stmt: { <NodeType>: body }, stmt_location?, stmt_len? }] }`.
parseSync before init throws "WASM module not initialized". Main entry ./wasm/index.cjs (CJS OK). Grammar version 160001.

node-pg-migrate 9 behaviour to mirror (verified, node_modules/node-pg-migrate/dist/bundle/index.js `function sql`):
  if (statement.lastIndexOf(";") !== statement.length - 1) statement += ";"
  (no trim: an Up section ending in "\n" gets ";" appended after the newline)
Marker regexes (byte-identical to scripts/migration-guard.js lines 73-74 and node-pg-migrate):
  /^\s*--[\s-]*up\s+migration/im  and  /^\s*--[\s-]*down\s+migration/im
  Up section = text.slice(upStart, downStart < upStart ? undefined : downStart)  (migration-guard.js extractUpSection)

Prototype to port (logic reference only; do not require it): 83-GUARD-RESEARCH.md "Appendix: Prototype", plus the
"Production version must-dos not in the prototype" list directly under it.
Case corpus to port: .planning/phases/83-postgres-infrastructure/83-13-allowlist-cases.reference.js
(a copy of the research scratchpad cases.js; 110 cases, 90 R / 20 A; results.txt showed 110/110 PASS with the prototype).
