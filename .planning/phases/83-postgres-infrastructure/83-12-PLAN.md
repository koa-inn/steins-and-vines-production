<objective>
Close verification gap 3 (REVIEW CR-04). The backfill's checks and promote gate must be able to fail when a sheet loaded nothing, or when a spec column is missing from the sheet or has been renamed.

Purpose: computeExpected builds its expectations from the ACCEPTED rows only. So 0 accepted out of N gives `Checks: PASS`, and `--promote --accept-rejects` "succeeds" with 0 rows. runBackfill never compares spec headers with the sheet, so a missing optional column becomes NULL in every row and still passes. This exact failure class happened in the 83-08 rehearsal. It was caught there only because the affected columns were required.
Output: A header-drift abort in backfill.js, a `read_vs_accepted` check and an empty-scratch promote refusal in load.js, README updates, and two new regression test files (one Docker-free, one real-Postgres).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| owner's .xlsx snapshot (sheet layout can drift) → backfill.js | Column headers are edited by staff in Sheets and can be renamed or deleted at any time |
| scratch schema → real table via promote (Phase 84+) | The promote gate is the last control before data reaches production tables |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-83-12-01 | Tampering (data integrity) | runBackfill header mapping | mitigate | A missing spec header aborts with EXIT.ERROR before normalise, load or connect. Unmapped headers are listed (Task 1) |
| T-83-12-02 | Tampering (data integrity) | runChecks vacuous pass | mitigate | The `read_vs_accepted` check fails when read > 0 and accepted === 0. backfill.js always passes counts.read (Task 2) |
| T-83-12-03 | Tampering | promote() of an empty scratch table | mitigate | Refuses before BEGIN and before touching the target, which keeps its row count at 0 (Task 2) |
| T-83-12-04 | Information disclosure | new terminal lines | mitigate | Only header labels and check names are printed, never cell values or expected/actual values. The existing summarizeChecks contract is unchanged (D-13) |
| T-83-12-05 | Tampering | runChecks callers that omit `read` | accept | Defaults to rows.length for back-compat with existing direct callers and tests. The only production caller (backfill.js) always passes it, and the Docker-free test pins that wiring |
| T-83-12-06 | Tampering | partial-reject sheets (e.g. 1 of 400 accepted) | accept | Not a vacuous pass: the rejects gate (exit 2 without --accept-rejects) and the PII rejects report already surface them. Accepting them is an explicit owner decision under D-12 |
</threat_model>
