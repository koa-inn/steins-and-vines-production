<objective>
Create the Past Sales router, register its paths as kiosk-scoped, and implement the ledger route end to end (classification, Vancouver-day bucketing, tender join, void-excluded totals, cache, caps).

Purpose: This is the server half of the Ledger tab (D-01 to D-04, D-14, D-16) and establishes the router, auth and validation scaffolding that 92-04 extends with the customer and invoice-detail routes.

ASSUMPTIONS (recorded, owner can override at review):
- A-05 The ledger queries invoices for `date_start=D, date_end=D+1` and payments for `date=D` and `date=D+1` (two payments list calls per day, plus paging) because every money path writes a UTC `date` (RESEARCH "UTC-date pitfall"). This is a small, documented deviation from D-14's literal "one customer-payments query per ledger day". If 92-01 found `customerpayments_date_range_honored: true`, use one ranged call `date_start=D, date_end=D+1` instead and drop the deviation.
- A-06 If 92-01 recorded `join_mode: 'detail-fallback'` AND the owner chose `approve-detail-fallback` at the 92-01 gate, tender and classification come from capped sequential invoice-detail fetches (MAX_TENDER_DETAIL_FETCH = 40) reading detail `payments[]` (note text from `_meta.detail_payments_notes_field`), cached per invoice under KIOSK_HISTORY_TENDER_PREFIX. Candidates past the cap are never silently dropped: they set `classification_incomplete` and are counted in `unclassified_count`.
- A-11 If 92-01 recorded `join_mode: 'none'`, the ledger applies the owner's 92-01 decision as NONE_BLANK_POLICY: `none-include-blank` -> 'include' (blank-reference invoices treated as in-store), `none-exclude-blank` -> 'exclude' (left out). Either way `classification_incomplete` is always true in this mode and `unclassified_count` = number of blank-reference invoices on the day. Tender still comes from the payments list when `_meta.linkage_field` is non-null, else tender is '' and `tender_incomplete` is true.
- STOP RULE: if JOIN_MODE is not 'list-join' and 92-01-SUMMARY has no "## Join-mode owner decision" (or the decision is `replan`), do not write code. Return a checkpoint to the orchestrator asking for the decision.
- Ledger date bounds: LEDGER_MIN_DATE = '2020-01-01'; dates after Vancouver today return 400.
</objective>
