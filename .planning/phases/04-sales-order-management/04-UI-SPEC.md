## Spacing Scale

Kiosk uses rem-based spacing derived from 16px base, mapped to 8-point grid:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (0.25rem) | Icon gap, chip internal padding (vertical) |
| sm | 8px (0.5rem) | Gap between chips, gap between action controls, card internal gap |
| md | 16px (1rem) | Card padding, section padding |
| lg | 20px (1.25rem) | Collect header/footer horizontal padding (matches existing .kiosk-collect-header) |
| xl | 32px (2rem) | Not used in this phase |
| 2xl | 48px (3rem) | Not used in this phase |
| 3xl | 64px (4rem) | Not used in this phase |

Exceptions:
- Status chip row vertical padding within collect header: 8px top, 8px bottom (0.5rem each)
- Minimum touch target for all interactive elements: 44px height (existing kiosk standard, enforced via min-height: 44px)
- SO card corner radius: var(--r-lg) = 8px (existing .kiosk-so-card pattern)
- Chip corner radius: 20px (pill shape, distinct from card radius)

## Color

All values from `css/kiosk.css` :root. No new color tokens introduced in this phase.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | var(--cellar-canvas) = #e8e2ca | View background |
| Secondary (30%) | var(--cellar-raised) = #faf8f2 | SO card background, collect header/footer background, chip inactive background |
| Accent (10%) | var(--stain) = #370e13 | Primary buttons (Pay, Import to Cart, Reorder), active chip border+text, focus ring |

Accent reserved for:
1. "Collect [amount]" pay button on actionable SO cards (open/draft)
2. "Import to Cart" button on actionable SO cards (open/draft)
3. Active status chip — border and text color when chip is selected
4. "Reorder" button on closed/paid SO cards
5. Focus ring (2px solid var(--stain)) on all interactive elements

Secondary semantic colors for status chips (read-only status indicators, not CTA):
- Open status chip active: var(--cellar-green) = #4a6f4b background, #fff text
- Draft status chip active: var(--barrel) = #77462d background, #fff text
- Closed status chip active: var(--ink-secondary) = #6b5442 background, #fff text
- Paid status chip active: var(--batch-success) = #3d7a40 background, #fff text
- All chip active: var(--stain) = #370e13 background, var(--cellar-canvas) text

Paid/closed SO card visual treatment:
- Border: 1px solid var(--ledger-line) (softened from --ledger-emphasis used on actionable cards)
- Opacity: 1 (full — staff needs to read these for reorder)

**Location:** Below `.kiosk-collect-header` actions row, above `.kiosk-so-list`. New row: `.kiosk-so-status-filter`.

**HTML pattern:**
```html
<div class="kiosk-so-status-filter">
  <button type="button" class="kiosk-so-chip kiosk-so-chip--open active" data-status="open">Open</button>
  <button type="button" class="kiosk-so-chip kiosk-so-chip--draft active" data-status="draft">Draft</button>

  <button type="button" class="kiosk-so-chip kiosk-so-chip--paid" data-status="paid">Paid</button>
```

## Interaction Contracts

### Status chip filtering
- All SOs fetched in one batch call with all statuses when collect view opens (client-side filter)
- Default active: Open + Draft chips
- Tap inactive chip: adds that status to active filter, re-renders list client-side
- Tap active chip (when >1 active): removes status, re-renders — minimum 1 chip always active (if tapping last active chip, no-op)
- Tap "All" chip: deactivates all individual chips, activates "All", shows entire fetched list
- Search box filters within the current chip-filtered set (same logic as existing search)

### Import to Cart (D-01 through D-05)
1. Staff taps "Import to Cart" on an actionable SO card
2. If `_kioskCart` has items: show `confirm()` dialog with copy above
3. On confirm (or if cart was already empty): clear cart, populate `_kioskCart` with SO line items, attach `_kioskImportedSoId = soId`, navigate to browse view
4. Browse view shows cart-SO-banner at top of cart pane
5. Staff may modify cart (add/remove/change qty) freely — no restrictions
6. Staff taps checkout — existing flow triggers, but middleware call updates the SO line items first, then collects payment

### Direct Pay (existing, unchanged for open/draft)
- Staff taps "Collect $XX.XX" button — existing `kioskCollectPayment(soId)` flow, no change

### Reorder (closed/paid SOs)
1. Staff taps "Reorder" on a closed/paid SO card
2. `confirm()` dialog: copy above
3. On confirm: call middleware to create a new SO with the same line items (customer + line items copied, new date, new SO number)
4. On success: show toast "New order created: [new SO number]", reload SO list (invalidate cache), default filter returns to Open+Draft (new SO will be visible)
5. On failure: show toast error "Could not create order. Try again."

### Post-payment lifecycle (D-07)
- After successful payment on an imported SO: show receipt (existing receipt display), then `kioskShowView('browse')` with empty cart and cleared `_kioskImportedSoId`
- Staff navigates back to SO list manually via nav button

### Payment retry on modified SO (D-08)
- If Zoho SO update succeeds but Helcim terminal fails: display error with "Retry Payment" button
- Retry re-enters terminal polling without re-updating the SO
- SO stays in Zoho as modified (do not revert)
