<objective>
Close feedback #3 / OPS-03 success-criterion #1: `GET /api/batch/search-invoices`
(`zoho-middleware/routes/pos.js:2262`) maps `inv.line_items || []` off the Zoho **list**
endpoint (`/invoices?search_text=`), which NEVER returns line items — so the field is always
empty and the BrewPad link-order UI can't show or match kit contents.

Fix: after the search resolves matching invoices, detail-fetch each one (`/invoices/{invoice_id}`)
to populate real `line_items`, mirroring the established search-then-detail pattern already used at
`pos.js:2449` (scan-invoices) and `pos.js:3125` (`/api/kiosk/salesorder/:id`). The list endpoint's
`invoice_id` is the numeric internal ID the detail endpoint needs.

Rate-limit discipline (constraint + Phase-57 WR-02): detail-fetching multiplies Zoho calls against
the ~1/s budget, so the number of detail-fetches per search MUST be hard-capped server-side.

Purpose: the link-order search returns usable kit contents without exhausting Zoho quota.
Output: a corrected search-invoices route + a middleware regression test.
</objective>
