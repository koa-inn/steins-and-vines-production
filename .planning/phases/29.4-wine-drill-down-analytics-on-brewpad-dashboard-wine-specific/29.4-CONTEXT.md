# Phase 29.4: Wine drill-down analytics on BrewPad dashboard - Context

**Gathered:** 2026-06-14
**Status:** Ready for planning

<domain>
## Phase Boundary

A wine-specific breakdown chart on the BrewPad dashboard that splits **wine batches**
by a **user-selectable dimension** (subcategory, brand, manufacturer, or kit time).
It renders as a **separate "Wine Breakdown" card below** the existing Phase 29.3
Batches-by-Month stacked chart, and derives the split attribute by joining
`batch.product_sku` → the static product catalog snapshot
(`content/zoho-snapshot.json`, `products[].sku`), since batches store only
`product_sku` / `product_name` today.

**Why this phase exists:** The 29.3 Batches-by-Month chart splits batches by beverage
type (wine/beer/cider/seltzer). Wine is by far the dominant type, and staff want to see
*what kind* of wine they're making (Red vs White, which supplier, which kit length, which
brand) — a single beverage-type bar can't answer that. The catalog snapshot already
carries the per-kit attributes; this phase joins it in.

**In scope:**
- A new "Wine Breakdown" card rendered below the existing Batches-by-Month chart in `js/brewpad.js`.
- Loading `content/zoho-snapshot.json` (products array) client-side and building a `sku → product` lookup.
- Joining wine batches to catalog products to derive the selected dimension value.
- A dimension selector (segmented buttons) over: subcategory, brand, manufacturer, kit time.
- Single aggregate horizontal-bar breakdown over the last-6-months window, sorted by count.
- Top-N + 'Other' collapsing for high-cardinality dimensions; 'Unknown' bucket for join/data gaps.
- 'time' value normalization + numeric (week-based) ordering for the time dimension.
- Tests (`js/brewpad.js` pure helpers, per project testing infrastructure).

**Out of scope:**
- Modifying the existing 29.3 Batches-by-Month chart (it stays untouched).
- Drill-downs for non-wine beverage types (beer/cider/seltzer).
- Server/middleware changes — this is frontend-only; no new API endpoint (reuse the static snapshot).
- Adding new attributes to the batch records or the Sheets schema.
- Persisting the selected dimension across page reloads (in-memory only).

</domain>

<decisions>
## Implementation Decisions

### Chart shape & placement
- **D-01:** The wine breakdown is a **separate "Wine Breakdown" card rendered below** the existing
  Batches-by-Month chart. The proven 29.3 chart is **not** modified — clean separation, lowest
  regression risk.
- **D-02:** Visual form is a **single aggregate breakdown** — one horizontal bar per dimension
  value, **sorted by batch count descending** (NOT stacked-by-month). This reads cleanly even for
  high-cardinality dimensions like brand.
- **D-03:** Batch window is the **same as the existing chart: last 6 months of started batches**
  (reuse the existing month-window logic / `start_date || created_at` convention from
  `bucketBatchesByMonthType`). Consistency with the chart directly above it.

### Default dimension & selector
- **D-04:** Default dimension on first load is **subcategory** (Red / White / Fruit / Rosé /
  Specialty — only 5 values, most intuitive "what kind of wine" split).
- **D-05:** Dimension selector is **segmented buttons** — `[Subcategory] [Brand] [Manufacturer]
  [Time]` — matching the clickable-chip/button vocabulary already used by the dashboard's legend
  toggle. One tap to switch.
- **D-06:** Selector state is **in-memory only** (resets to subcategory on reload). No
  localStorage persistence (Claude's discretion to keep it consistent with existing in-memory
  chart state like `_dashChartHiddenTypes`).

### Top-N + 'Other' grouping
- **D-07:** Collapse to **top 8 + 'Other'**: show the 8 highest-count values for a dimension,
  fold the remaining tail into a single 'Other' bucket.
- **D-08:** Top-N is a **generic rule applied to ANY dimension whose distinct count exceeds 8**
  (so brand, ~19 distinct, collapses; subcategory(5) / manufacturer(4) / time(5) show every
  value). Not hardcoded to brand.
- **D-09:** **'Other' always sorts last**, regardless of its aggregate count.

### Join edge cases & data hygiene
- **D-10:** A wine batch whose `product_sku` has **no catalog match**, or whose matched product
  has an **empty value** for the selected dimension, goes into a distinct **'Unknown' bucket that
  sorts after 'Other'**. Surfaces data gaps honestly rather than hiding them; 'Unknown' is kept
  separate from the 'Other' long-tail bucket.
- **D-11:** **Wine membership** is determined by the existing **`resolveBatchType(batch, …) === 'wine'`**
  classifier (batch.category / schedule_id lookup / schedule_snapshot) — the SAME logic the chart
  above uses. The catalog SKU join is used **only to derive the dimension value**, never to decide
  whether a batch is wine. A wine batch with no catalog match still counts — its dimension is 'Unknown'.
- **D-12:** The **'time' dimension is normalized** (merge singular/plural variants, e.g.
  `'5 week'` → `'5 weeks'`) and, for the time dimension specifically, **bars are sorted by week
  number ascending (4, 5, 6, 8 weeks)** instead of by count. All other dimensions remain
  sorted by count (per D-02).

### Claude's Discretion
- **Bar colors:** reuse/extend the existing dashboard palette with a deterministic per-value
  color assignment (stable across renders for a given dimension). No fixed brand→color contract.
- **Empty state:** card shows a friendly "no wine batches in the last 6 months" message when the
  window yields zero wine batches.
- **Totals label / bar value display:** show per-bar counts and a total; exact formatting is
  discretionary, consistent with existing chart styling.
- **Snapshot fetch:** fetch `content/zoho-snapshot.json` once and cache client-side; failure to
  load degrades gracefully (card hidden or shows a load-error note) without breaking the rest of
  the dashboard.
- **Accessibility:** mirror the existing chart's a11y conventions (roles, aria-pressed on the
  segmented buttons like the legend chips).

</decisions>

- In-memory chart UI state (e.g., `_dashChartHiddenTypes`) — selector state follows the same in-memory approach (D-06).
- Pure helper functions exported for Jest (`module.exports` guard) — new bucketing/normalization helpers should be pure + testable.
- Wine is identified in the catalog by `type === "Wine"` (238/250 products); `_zoho_category` is empty in the snapshot — do NOT key off it.

### Integration Points
- New "Wine Breakdown" card injected into the dashboard render path immediately after the Batches-by-Month chart block in `js/brewpad.js`.
- New client fetch of `content/zoho-snapshot.json` (or reuse if already loaded elsewhere on the dashboard) → `sku → product` lookup map.

<specifics>
## Specific Ideas

- Wine dimension cardinality observed in the current snapshot (catalog, 238 wine products):
  - **subcategory** (5): Red 130, White 80, Fruit 13, Rosé 12, Specialty 3
  - **brand** (19, open set): Classic 23, Original Series 23, Cru International 22, Reserve 21, Estate Series 20, En Primeur 18, … (long tail) → top-8 + Other
  - **manufacturer** (4): RJS Craft Winemaking 88, Winexpert 83, VineCo 64, (empty) 3
  - **time** (messy): "4 weeks" 101, "6 weeks" 61, "8 weeks" 51, "5 weeks" 23, "5 week" 2 → normalize + numeric sort
- Note: these are *catalog* counts; the chart counts *batches*, whose distribution will be more skewed — top-N collapsing operates on actual batch counts.

</specifics>
