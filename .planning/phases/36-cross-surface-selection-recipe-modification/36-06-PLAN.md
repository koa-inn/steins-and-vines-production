<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| BrewPad iPad -> Apps Script updateBatch | Modified ingredient list + scaled snapshot are client-built and written to the batch record; attach has no money path. |
| BrewPad iPad -> POST /api/recipes | Save-as-new sends a recipe name + ingredient list. |
| dynamic HTML rendering | Ingredient names rendered into modify rows + advisory list. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-17 | Tampering | client-built snapshot quantities | accept | Attach is record-keeping only — no charge and no inventory deduction occurs (D-10), so a tampered snapshot quantity has no financial/stock-integrity impact; it only records intended brew quantities. Stock advisory is informational. Accepted per D-10/D-11 design. |
| T-36-18 | Injection (XSS) | ingredient/recipe names in modify rows + advisory | mitigate | escapeHTML wraps all dynamic names rendered via innerHTML (project rule). Test injects a malicious name and asserts escaping in the rendered advisory + row. |
| T-36-19 | Spoofing | save-as-new without auth | mitigate | POST /api/recipes carries x-api-key (mwApiKey) and is subject to the existing middleware guards + activation guardrail; status:'draft' means it cannot go live without passing the guardrail in a later activation step (recipes.js PUT). |
| T-36-20 | Tampering | attach accidentally invoking the charge path | mitigate | Attach handler builds a snapshot and calls only adminApiPost('update_batch'); a test asserts no recipe-quote/recipe-sale/Helcim call fires on attach (D-10 enforced by test). |
| T-36-SC | Tampering | npm/pip installs | accept | No new packages. No package legitimacy gate required. |
</threat_model>
