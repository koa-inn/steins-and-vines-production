## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Tests assert the buggy behavior | Twice this session an executor's tests "passed" while encoding the bug: (1) `T1d` in kiosk-recipe-quote asserted the OLD no-fetch-without-sale-type behavior; (2) 36-20 tests asserted `cache.set` got a raw object when it must be a `JSON.stringify`'d string. | advisory | When fixing a bug, read the existing tests for that path FIRST and confirm they don't codify the bug; update assertions to the corrected behavior. |
| Terminal-result cache double-encode | `cache.set` JSON.stringifies and `cache.get` JSON.parses, and `pollTerminalResult` JSON.parses AGAIN — so values cached under `helcim:terminal:result:{invoice}` MUST be pre-`JSON.stringify`'d strings (the working terminalCancel path does this). A raw object silently misses the cache. | advisory | Match the cancel-path convention for any terminal-result cache write. |
| Middleware has no staging isolation | One Railway instance (`sv_middleware`) serves BOTH staging and prod frontends. "Staging first" cannot isolate a middleware change. | advisory | Test middleware locally (full `cd zoho-middleware && npm test`), then `railway up` = live for everyone; only do it for changes that can't make things worse. |
