# Phase 36 Plan 22: BrewPad Save-Refresh Staleness Fix Summary

**One-liner:** Added `afterBatchWrite(batchId, opts)` helper that removes the `sv-bp-batch-{id}` sessionStorage snapshot, clears in-flight preloads, and resets list/dashboard state — applied to all 10 offender handlers identified in the audit so saves are reflected immediately on re-open.

## What Was Built

### afterBatchWrite helper (~L1866 in js/brewpad.js)

A single shared cache-busting function called after every successful batch write:

- **(A)** `sessionStorage.removeItem('sv-bp-batch-' + batchId)` + cancels any in-flight preload for that id
- **(B)** Resets `_batchesLoaded=false; _allBatchesData=[]; _eagerLoadTime=0; _dashLoadTime=0` unless `opts.listAffecting === false`
- **(C)** If `opts.refreshOpenDetail && _selectedBatchId === batchId`: re-fetches from server and re-renders the open detail pane

### Recipe list freshness

After inline recipe create, attach, and save-as-new operations, `loadRecipeList('all')` is now called on success so the recipe list panel reflects the new/updated recipe immediately. `saveRecipe` (the main recipe manager) already did this correctly.
