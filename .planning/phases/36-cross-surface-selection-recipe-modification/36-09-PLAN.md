|----------|-------------|
| admin browser → /api/kiosk/recipe-quote | Client sends recipe_id + target_volume_l (+ modified_ingredients); server returns the authoritative price. The new factor input only changes the displayed target_volume_l. |
| admin browser → /api/ingredients | Catalog fetch for the modify-panel autocomplete (loaded on panel open). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-09-01 | Tampering | ×factor → price | mitigate | The factor↔litres sync is client-side display only; the charge comes from the server quote (FAC-5 asserts re-quote, not a client price). Code comment + test lock this so the factor can never become the source of the charge. |
| T-36-09-02 | Tampering / XSS | modify-row ingredient + recipe names | mitigate | New/edited ingredient-row rendering reuses the existing escapeHTML path (renderKioskModifyRows); the static "× factor" label needs no escaping. Verify no raw interpolation of catalog names is introduced. |
| T-36-09-03 | Denial of service | debounced re-quote on factor input | accept | Re-quote reuses the existing 350 ms debounce (kioskScheduleRecipeQuote); the factor handler routes through the same debounce, so no new request-amplification path. |
| T-36-09-SC | Tampering | npm installs | accept | No new package installs in this plan — only existing devDeps (jest, terser, cleancss) via npm run build/test. No package legitimacy gate needed. |
