## Surface-by-Surface Interaction Contract

### 1. Admin Recipe-Sale Surface (`admin.html#kiosk-recipe-prompt`)

**Existing from Phase 35 (LOCKED — do not redesign):**
- `#kiosk-recipe-volume-wrap`: label "Target volume (L)" + `#kiosk-target-volume` number input (min 0.5, step 0.5, inputmode decimal, pre-fill `batch_size_l`)
- `#kiosk-scale-factor-readout`: renders `"1.5× base 20 L"` string; weight 600, color --ink-secondary
- `#kiosk-stock-conflict`: hard-block panel with short ingredients list + "Manager Override — Proceed Anyway" btn-secondary
- No-base-size disabled state: input disabled + readout = "Set batch size (L) on the recipe to enable scaling"

**Net-new for Phase 36 — Ingredient Modification Panel:**

Placement: insert `#kiosk-recipe-modify-wrap` immediately after `#kiosk-recipe-volume-wrap`, before `#kiosk-stock-conflict`. The full order inside `#kiosk-recipe-prompt` is:
1. Back button + recipe name
2. `#kiosk-recipe-summary` (grouped ingredient display)
3. `#kiosk-recipe-volume-wrap` (LOCKED from Phase 35)
4. `#kiosk-recipe-modify-wrap` (NEW)
5. `#kiosk-stock-conflict` (LOCKED from Phase 35)
6. `#kiosk-avail-banner`
7. Sale-type buttons + milling toggle + Add-to-Cart button

**`#kiosk-recipe-modify-wrap` layout:**

```
[ Modify Ingredients  ▼ ] ← collapsible toggle button (.btn-secondary, collapsed by default)
  ┌──────────────────────────────────────────────────────────┐
  │  Ingredient rows (table, reuses .recipes-ing-row pattern) │
  │  [search autocomplete] [qty] [unit] [× remove]           │
  │  ...                                                     │
  │  [+ Add Ingredient]                                      │
  └──────────────────────────────────────────────────────────┘
  Price preview: "Estimated total: $XX.XX  (updates after 350 ms)"
  Locked-price notice (conditional, see below)
```

- Toggle button label: "Modify Ingredients" (collapsed) / "Modify Ingredients ▲" (expanded). Default: collapsed. Toggling does not reset the ingredient state.
- When expanded: renders a `<table>` with class `kiosk-recipe-modify-table` using the same column structure as the admin recipe-builder table (`recipes-ing-row` pattern: autocomplete column, qty column, unit column, remove column). Cost/retail columns are omitted in this context — only qty and unit shown.
- Ingredient rows: each row uses classes `.kiosk-modify-row`, contains:
  - `.ing-autocomplete-wrap` column: `<input type="text" class="admin-input ing-search" />` (min-height 44px for touch target; font-size 1rem on kiosk surface)
  - qty column: `<input type="number" class="admin-input ing-qty" step="0.01" min="0" inputmode="decimal" />`
  - unit column: `.ing-unit` text span (auto-populated from catalog selection)
  - remove column: `<button type="button" class="btn-secondary ing-remove">&#10005;</button>` (min 44px × 44px)
- "Add Ingredient" affordance: `<button type="button" class="btn-secondary" id="kiosk-modify-add-row">+ Add Ingredient</button>` below the table, left-aligned
- Substitution: implemented as remove + add (D-05 data-level). No separate "swap" affordance exposed.
- Autocomplete dropdown: reuses existing `.ing-autocomplete-drop` class (position absolute, max-height 200px, overflow-y auto, z-index above table rows)

**Price preview panel (`#kiosk-recipe-price-preview`):**
- Position: below ingredient table, above stock-conflict panel
- Content: `"Estimated total: $XX.XX"` — value sourced from `GET /api/kiosk/recipe-quote` dry-run with 350 ms debounce (D-06, extends Phase 35's quote endpoint)
- Style: background --cellar-raised, border 1px solid --ledger-line, border-radius --r-md, padding --sp-3 --sp-4, font-size 13px
- Loading state: "Calculating…" in --ink-tertiary while debounce pending
- Error state: "Price unavailable — check connection" in --batch-danger

**Locked-price asymmetry notice (D-07/D-08):**
- Shown only when `pricing_mode === 'locked'` AND the modify panel has been expanded at least once
- Text: "Adding ingredients increases the price. Removing ingredients does not reduce it."
- Style: font-size 11px, color --ink-tertiary, margin-top --sp-2, no border or icon
- Position: below price preview, above stock-conflict panel

**Modified flag in Add-to-Cart button:**
- When any modification has been made (ingredients differ from the original recipe template), the Add-to-Cart button label changes from "Add to Cart" to "Add to Cart (Modified)"
- Same `.btn` class + --stain styling; no additional visual treatment beyond the label suffix

**Save-as-New-Recipe affordance (D-14, MOD-03):**
- Shown only when ingredient modifications exist
- Placement: inline link below the Add-to-Cart button — `<button type="button" class="admin-btn-sm" id="kiosk-save-as-new-btn">Save as new recipe</button>` — secondary treatment (not the primary CTA)
- On click: inline name prompt — `<div id="kiosk-save-as-new-prompt">` appears below with: `<input type="text" id="kiosk-new-recipe-name" placeholder="New recipe name" />` + `<button class="btn">Save Draft</button>` + `<button class="btn-secondary">Cancel</button>`
- Success feedback: "Recipe saved as draft. Activate in admin to use." — inline below the prompt in --batch-success color
- Draft/inactive indication: the notice communicates inactive status via the word "draft" — no badge or icon needed here
- Error feedback: "Could not save recipe — try again." in --batch-danger

### 2. Kiosk Recipe-Sale Surface (`kiosk.html#kiosk-recipe-prompt`)

**Current state:** `kiosk.html` `#kiosk-recipe-prompt` does NOT yet have the Phase 35 target-volume control. Phase 36 ports it from admin.html (SEL-01).

**Placement of ported Phase 35 control:**
Insert `#kiosk-recipe-volume-wrap` and `#kiosk-stock-conflict` into `kiosk.html` `#kiosk-recipe-prompt` at the same relative position as in admin.html — after `#kiosk-recipe-summary`, before `#kiosk-avail-banner`:
1. Back button + recipe name (`#kiosk-recipe-selected-name`)
2. `#kiosk-recipe-summary`
3. `#kiosk-recipe-volume-wrap` (PORT from admin.html, identical markup)
4. `#kiosk-recipe-modify-wrap` (NEW — same as admin surface, see above)
5. `#kiosk-stock-conflict` (PORT from admin.html, identical markup)
6. `#kiosk-avail-banner`
7. Sale-type buttons + milling toggle + Add-to-Cart button

**Touch-friendliness for kiosk iPad:**
- All inputs: `font-size: 1rem` (≥16px, prevents iOS zoom)
- All buttons: `min-height: 44px`, `min-width: 44px`
- The quantity input (`ing-qty`) on kiosk: `inputmode="decimal"`, width sufficient for 4-digit numbers (min 64px)
- The autocomplete search input: full-width within its column, `inputmode="search"` or `inputmode="text"`
- The "Modify Ingredients" toggle button: min-height 44px, padding 12px 24px (btn-secondary standard)
- The autocomplete dropdown rows: `padding: 14px 12px` per option to hit 44px effective tap height
- The "Add Ingredient" button: min-height 44px (standard btn-secondary)
- The Remove (×) button: `min-height: 44px; min-width: 44px` centered within its cell

**Permission boundary (D-05 Claude's Discretion):** Ingredient modification is available to all kiosk staff without additional permission gating. The kiosk is a staff-only in-store iPad POS — same access level as admin.

**Save-as-New-Recipe on kiosk:** Not exposed. Save-as-new is an admin/BrewPad action only. The kiosk surface focuses on completing the sale; recipe management is for admin/BrewPad. The modified ingredient list still flows into the sale/snapshot (MOD-02) — the save affordance is just absent.

**Volume control (port of Phase 35, D-01):**

**Ingredient modification on BrewPad (D-03):**
- Same collapsible "Modify Ingredients" toggle pattern as admin/kiosk

**No price preview on BrewPad (D-10):**

## Grouped Ingredient Display in Modify Panel

When the modify panel is opened, existing recipe ingredients are rendered in their grouped-by-cf_type order using `groupRecipeIngredients` (js/lib/recipe-grouping.js, Phase 34). Each group renders:
- A group header row (`<tr class="kiosk-modify-group-header">` or `.bp-recipe-ing-group`): cf_type label in 11px uppercase 700 weight --ink-tertiary, spanning all columns
- Ingredient rows within the group

When an ingredient is added via autocomplete and its cf_type is known from the catalog, it is appended to the bottom of its type group. If cf_type is unknown/blank, the row appends at the end of the list below all groups.

When an ingredient is removed, its row is deleted immediately. The group header for an empty group is also removed.

## Implementation Notes for Executor

1. **Never edit `js/main.js` / `*.min.js` directly.** Admin surface code lives in `js/admin.js`. Run `npm run build` after any source change.
2. **kiosk.js and brewpad.js are standalone bundles** — they are not concatenated by the main build. Edit `js/kiosk.js` and `js/brewpad.js` directly, then run `npm run build` to regenerate their `.min.js` counterparts.
3. **ES5/`var` throughout.** No arrow functions, const/let, template literals, or spread in any `.js` file that is not already using them. Use `escapeHTML` for all dynamic HTML insertion.
4. **The `.admin-input` class on kiosk surface** may need an override in admin.css (or inline style) to set `font-size: 1rem` for iOS zoom safety — the base `.admin-input` is 13px.
5. **Autocomplete dropdown z-index:** ensure `.ing-autocomplete-drop` on kiosk sits above the kiosk-recipe-prompt scroll container. Existing admin.css sets position:absolute; verify z-index stacking in kiosk context.
6. **BrewPad attach scroll:** the batch detail pane scrolls; the expanded modify panel adds height. No overflow changes needed — the existing `overflow-y: auto` on `.bp-panel-inner` handles it.
7. **Quote endpoint extension (D-06):** `GET /api/kiosk/recipe-quote` must accept an optional `modified_ingredients` array in addition to `recipe_id` and `target_volume_l`. Server computes the quote on the modified list. Middleware unit tests required per CONTEXT `code_context`.
