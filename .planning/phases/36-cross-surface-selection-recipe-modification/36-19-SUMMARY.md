# Phase 36 Plan 19: BrewPad Recipe List Style + Clone Summary

**Recipe list shows style as a compact muted sub-line under the recipe name; Clone button in the editor opens a deep-copy draft pre-named "Copy of {name}" with status=draft and no recipe_id — nothing saved until the user presses Save.**

## Accomplishments

- Feature 1 — Recipe list style: `renderRecipeListHtml()` pure helper renders `<div class="bp-recipes-style">` under the recipe name cell only when `recipe.style` is non-empty; `escapeHTML` applied; `.bp-recipes-style` CSS rule added (muted 0.78rem body font, `var(--ink-tertiary)`)
- Feature 2 — Clone button: `bp-recipe-clone` button added to `brewpad.html` detail-actions (hidden in new-recipe mode via `openRecipeDetail`); `bpCloneRecipePayload()` builds a deep copy (name="Copy of …", status="draft", recipe_id=null, all fields + ingredient rows copied); `bpCloneRecipe()` loads the copy into `_recipesState` and calls existing `populateRecipeForm` + `renderIngredientRows` without any fetch
- 20 new tests in `tests/frontend/brewpad-recipe-list-clone.test.js` covering both features; all 893 frontend + 897 middleware tests green; lint 0 errors

## Files Created/Modified

## Decisions Made

- Extracted `renderRecipeListHtml` as a pure function (takes `recipes[]`, returns HTML string) so the list rows are testable without a DOM — `renderRecipeList` remains the DOM-writing consumer
- `bpCloneRecipePayload` is pure (no side effects); `bpCloneRecipe` is the state-coupled action that calls it — enables testing the clone invariants (no mutation, no fetch) without mocking the DOM
- Both new functions exported via the IIFE's inner `Object.assign` block (same pattern as `bpSaveAsNewRecipe`), because they are IIFE-scoped

## Deviations from Plan

None — plan executed exactly as written.

## Issues Encountered

The first export attempt put `renderRecipeListHtml` and `bpCloneRecipePayload` in the outer export block (after `})();`), which can't reference IIFE-scoped names. Moved them to the inner `Object.assign` block inside the IIFE — this is the established pattern for IIFE-scoped functions in this codebase. Fixed immediately during GREEN phase; no extra commits.
