<objective>
Wire modified ingredient lists into the three server money-path entry points: the shared `computeRecipeQuote` helper (used by both the quote endpoint and `POST /api/kiosk/recipe-sale`), AND the separate inline scaling block in the `/recipe-sale/confirm` handler. This is MOD-02 — the modified list is priced server-authoritatively and captured in invoice + snapshot.

Purpose: Phase 35 left two separate pricing code paths (computeRecipeQuote and the inline confirm block). Both must honor the modified list or the displayed-==-charged guarantee breaks for modified sales.
Output: Extended routes + middleware tests covering quote, recipe-sale, and confirm with modified lists, plus the snapshot fields.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (admin/kiosk) -> /api/kiosk/recipe-quote, /recipe-sale, /confirm | Client supplies modified_ingredients (item_ids + base quantities + names). Untrusted: rates, prices, and recipe identity must come from the server. |
| route -> Zoho invoice + frozen snapshot | Modified ingredient names flow into invoice line descriptions and the snapshot JSON. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-06 | Tampering | client-supplied price/rate on modified lines | mitigate | Server re-fetches the recipe (get_recipe) and reads all rates from cache INGREDIENTS_ALL catalogMap; computeModifiedRecipeTotal never reads a client rate/price field. The charged total comes only from the server compute, never from the request body. |
| T-36-07 | Tampering | added item_id not in catalog | mitigate | Added lines with no catalogMap[item_id] are skipped (no price contribution) rather than trusting a client-sent rate — cannot inflate or deflate the charge with a fabricated item. Add a test for an unknown added item_id (priced as 0 contribution). |
| T-36-08 | Tampering | bypass scaled-stock gate via modified list | mitigate | checkScaledStock runs on the scaled MODIFIED quantities in the confirm handler; the existing 409 + manager-override gate is preserved. |
| T-36-09 | Injection | ingredient/recipe names into invoice + snapshot JSON | mitigate | Snapshot is JSON.stringify'd (no HTML); invoice line descriptions are sent to Zoho as data fields, not interpolated into markup. Server-side names are used; verify no raw concatenation into a query/HTML sink in the new code. |
| T-36-10 | Elevation of Privilege | unauthenticated modified sale | mitigate | These routes already sit behind the MW_API_KEY guard + BEER_SALES_ENABLED gate (Phase 32/35); no change weakens them. Kiosk is staff-operated. |
| T-36-SC | Tampering | npm/pip installs | accept | No new packages. No package legitimacy gate required. |
</threat_model>
