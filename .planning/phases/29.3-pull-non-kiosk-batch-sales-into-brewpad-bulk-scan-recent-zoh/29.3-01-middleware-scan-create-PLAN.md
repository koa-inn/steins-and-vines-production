<objective>
Add the backend for the BrewPad "Pull from Zoho" feature: a bounded, rate-limit-aware
scan that finds ferment-in-store invoices (Maker's Fee present) with no batch yet, and a
server-authoritative bulk-create that turns confirmed candidates into pending batches.

Purpose: Invoices completed directly in Zoho Books never run the kiosk/online batch-create
path, so no BrewPad batch appears. This endpoint closes that gap without touching the
existing checkout path.

Output: Two new handlers in zoho-middleware/routes/pos.js
(`GET /api/batch/scan-invoices`, `POST /api/batch/bulk-create`) plus a Jest test file.
</objective>

  url          = process.env.APPS_SCRIPT_URL

  get_batches is a doGet action. CRITICAL: Apps Script adminApi.gs reads the server-auth token from
  e.parameter.server_token (adminApi.gs ~line 95). e.parameter.token (~line 402) is a DIFFERENT param —
  it is validated as a Google OAuth access token via Google's tokeninfo API and will FAIL for the server
  token. Therefore call via:
    axios.get(url, { params: { action:'get_batches', server_token: process.env.APPS_SCRIPT_SERVER_TOKEN, status:'all' } })
  Passing the server token under `token:` returns { ok:false, error:'unauthorized' } → empty dedup set →
  D-10.1 silently does nothing (every previously-batched invoice reappears as a candidate).
  response shape: { ok:true, data:{ batches:[{ zoho_so_number, batch_id, ... }], total, filtered } }
