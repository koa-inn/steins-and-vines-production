### Human Verification Required

#### 1. Pull from Zoho button opens confirm sheet with scan results

**Test:** Open BrewPad, navigate to the Batches tab. Observe the filter bar for a "Pull from Zoho" button. Click it.
**Expected:** A confirm sheet (`bp-pull-sheet`) opens immediately. A loading indicator appears while `GET /api/batch/scan-invoices` fires. Results are rendered: candidate invoice rows (with invoice number, customer name, kit items) or a "No new invoices found to import" info toast if none qualify.
**Why human:** DOM interaction, fetch lifecycle, and rendered output cannot be verified by automated tests in this repo.

#### 2. DRAFT badge visible on draft-status invoice candidates

**Test:** During the scan (or by importing a known draft invoice via single-import), observe whether draft invoices show an orange DRAFT badge in the candidate row.
**Expected:** Invoices with `status === 'draft'` display a DRAFT badge. Paid/sent invoices do not.
**Why human:** The `buildPullCandidateRowHtml` helper is tested in Jest, but visual rendering in the real DOM requires human confirmation.

#### 3. Single-import field validates and resolves correctly

**Test:** In the pull sheet, type an invalid format (e.g., "ORDER-123") into the import field and click Import. Then type a valid number (e.g., "INV-000100") and click Import.
**Expected:** Invalid input shows "Enter a valid INV-XXXXXX or SO-XXXXXX number" warn toast without any network call. Valid input resolves the invoice via `scan-invoices?number=INV-000100` and either adds it as a candidate or shows "No importable invoice found."
**Why human:** Requires a live middleware + Zoho connection.

#### 4. MANDATORY: Redeploy apps-script/adminApi.gs before going live

**Test:** After manually redeploying `apps-script/adminApi.gs` to the Google Apps Script project, attempt to create a batch with a `zoho_so_number` that already exists in the BATCHES sheet (e.g., via a second scan + create for the same invoice).
**Expected:** The duplicate create returns `{ ok: false, error: 'duplicate_so_number', message: 'A batch for SO/invoice INV-XXXXX already exists: SV-B-NNNNNN' }`. The middleware per-row result surfaces this error.
**Why human:** `adminApi.gs` is hand-deployed to Google. The guard at lines 1905–1922 exists in source but has ZERO effect in production until manually redeployed. This is explicitly flagged in the plan 02 SUMMARY as a pre-ship requirement.
