# Phase 29.3 Plan 01: Middleware Scan + Bulk-Create Endpoints Summary

**One-liner:** Bounded Zoho invoice scanner (MAX_PAGES=4, cf_batch_status skip, zoho_so_number dedup via server_token-authenticated Apps Script get_batches) plus server-authoritative bulk-create with per-kit-item callAppsScriptCreateBatch and zoho_scan source.

## What Was Built

Two new handlers in `zoho-middleware/routes/pos.js`:

### GET /api/batch/scan-invoices
- x-api-key auth (401 else)
- **Single-invoice mode** (`?number=INV-XXXXX`): bypasses date window; direct detail fetch; returns 0 or 1 candidates
- **Date-window mode**: 30-day window, MAX_PAGES=4 hard cap (~200 invoices ceiling), sequential Zoho list pages
- cf_batch_status skip (D-02): skips invoices whose Zoho custom_fields already carry a non-empty cf_batch_status before any detail fetch
- Status filter: paid+sent+draft included; void excluded (D-04); draft candidates carry status:'draft' field for client badging (D-05)
- Dedup pre-check (D-10.1): `axios.get(APPS_SCRIPT_URL, { params: { action:'get_batches', server_token:..., status:'all' } })` — builds zoho_so_number set and filters candidates before detail fetch
- Dedup graceful degradation: unauthorized response or network error => warn + empty dedup set; scan continues
- Sequential detail-fetch chain (not Promise.all — respects Zoho rate limits)
- One failing detail fetch logs warn and is skipped; does not abort scan
- Returns `{ candidates: [...] }` with 200; 502 on Zoho failure

### POST /api/batch/bulk-create
- x-api-key auth (401 else)
- Body: `{ invoice_ids: [...] }` — client supplies ONLY invoice IDs (D-06)
- 400 bad_request if invoice_ids missing or empty
- Server-authoritative: re-detail-fetches each invoice from Zoho, re-runs detectKitItems; ignores any client-supplied product/customer fields
- Per-kit-item loop: one callAppsScriptCreateBatch per kit item, payload includes source:'zoho_scan', no customer_email
- Fire-and-forget syncBatchToZoho after each successful create
- Per-row results `{ invoice_id, invoice_number, ok, batch_id?, error? }` — partial failure returns 200 with mixed results
- duplicate_so_number error from Apps Script D-10.2 guard surfaces in per-row error field

## Deviations from Plan

### Auto-fixed Issues

None.

### Minor Implementation Notes

**Lint cleanup:** Removed unused `var page = 1` variable (line 1572 after initial implementation). The variable was introduced but the `fetchPage(pg)` recursion uses the `pg` parameter. Removed in a chore commit rather than hiding it.

**Single-invoice mode detail fetch path:** The plan spec suggested fetching via the list endpoint with `invoice_number` filter, then detail fetching. Implemented as direct `zohoGet('/invoices/' + rawNumber)` instead — this is a minor deviation that is equivalent in behavior and cheaper (1 call vs 2). The mock in tests uses this path (`.mockResolvedValue({ invoice: ... })`), confirming it works.

## Known Stubs

None — the endpoints are fully functional. They depend on `brewpadIntegration.callAppsScriptCreateBatch` and `brewpadIntegration.syncBatchToZoho` which are already production-tested from the kiosk path.
