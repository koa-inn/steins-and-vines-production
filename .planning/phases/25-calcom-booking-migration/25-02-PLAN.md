FRONTEND READ POINTS (js/modules/12c-checkout-scheduling.js — MUST NOT CHANGE; these are what the response must satisfy):
- availability: `(data.dates || []).forEach(d => avail[d.date] = { available:true, slots: d.slots_count || 0 })` — needs `dates:[{date, slots_count}]`.
- slots: `var slotList = data.slots || []; var time = s.time || s; time.match(/(\d+):(\d+)\s*(AM|PM)/i)` — needs `slots:[{time:"10:00 AM"}]` (12-hour). Bare strings also accepted but emit `{time}`.
- POST: response not deeply parsed by 12c; 12-checkout.js consumes `{ok, booking_id, timeslot}`.

ADAPTER (zoho-middleware/lib/calcom.js — from Plan 01):
- `listEventType(id)` -> resolves to event-type object data (id, title, slug, lengthInMinutes, description, price, currency, bookingUrl).
- `getSlots(eventTypeId, start, end, timeZone)` -> resolves to `{ "YYYY-MM-DD": [ { start: "2026-06-05T09:00:00.000-07:00" }, ... ], ... }` (the `.data` of the Cal.com response).
- `createBooking(body)` -> resolves to Cal.com booking data `{ id, uid, status, start, end, attendees }`.

REUSE from zoho-api.js:
- `normalizeTimeTo24h("10:00 AM")` -> "10:00:00" (for building the POST start instant). KEEP using it.

EXISTING route mechanics to preserve verbatim (from current routes/bookings.js):
- Cache: AVAILABILITY_CACHE_PREFIX / SLOTS_CACHE_PREFIX / BOOKING_SERVICES_CACHE_KEY + TTLs (300/300/86400) from C.CACHE_KEYS.
- All POST validation: missing date/time, missing customer name/email, date regex /^\d{4}-\d{2}-\d{2}$/, email length/@ check, name<=200, phone<=30, notes<=1000.
- Offline fallback: `if (req.zohoOffline)` returns 201 { ok:true, booking_id:'PENDING-...', timeslot: date+' '+time }. KEEP this exactly (the variable name req.zohoOffline stays — it gates the same "provider unauthenticated" path).
- Cache invalidation on successful POST: del availability key for the month + slots key for the date.

CONVERSION RULES (RESEARCH Patterns 1-3):
- ISO slot start -> 12h label: `new Date(start).toLocaleTimeString('en-US',{hour:'numeric',minute:'2-digit',hour12:true,timeZone:'America/Vancouver'})`.
- Month availability: ONE getSlots call for the whole month range; group by date key; emit only days with length>0 as {date, available:true, slots_count:N}. Do NOT port Zoho's per-day batch-of-5 fan-out (Pitfall 3).
- POST start (UTC): combine body.date + normalizeTimeTo24h(body.time), interpret in America/Vancouver, convert to UTC ISO with trailing Z (Pitfall 2). Always send attendee.timeZone='America/Vancouver'.
- services: drive from CALCOM_EVENT_TYPE_* env ids via listEventType per id (Pitfall 5 — do NOT list all event types). Emit { services:[mapped event types], staff: [] } (frontend ignores staff; A6 verified safe).
- POST booking_id <- data.uid (preferred stable string); timeslot <- body.date + ' ' + body.time (unchanged).
- phone -> metadata.phone (Cal.com attendee has no first-class phone field).
