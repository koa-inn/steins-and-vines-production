From zoho-middleware/lib/zoho-api.js (style + retry to reuse):
- `withRetry(fn, opts)` — exported; wrap axios calls with this for 429/5xx backoff.
- `bookingsGet(path, params)` / `bookingsPost(path, body)` — the helpers being replaced; mirror their shape: build URL, attach headers, axios call, return response.data.
- `normalizeTimeTo24h(timeStr)` — "10:00 AM" -> "10:00:00"; KEEP and reuse for the POST path (do NOT remove).
- Module uses ES5: `var`, function declarations, `module.exports = { ... }`.

From zoho-middleware/lib/helcim.js (webhook verify pattern to mirror, simplified):
- `verifyWebhookSignature(...)` — reads secret from env; if secret missing, log.warn + return true (fail-open dev pattern); computes HMAC; compares with crypto.timingSafeEqual inside try/catch (length mismatch -> false).
- For Cal.com: SINGLE header `x-cal-signature-256`, HMAC-SHA256, HEX digest (not base64, not the Helcim/Svix triple). Sign over the raw body string.

Cal.com API v2 facts (from RESEARCH §1-§6 — CITED):
- Base: `https://api.cal.com/v2`
- Auth header: `Authorization: Bearer <CALCOM_API_KEY>`
- cal-api-version (MANDATORY, per-endpoint, dated): event-types `2024-06-14`, slots `2024-09-04`, bookings `2026-02-25` (CONFIRM bookings value against live doc at build).
- `GET /v2/event-types/{id}` — single event type by numeric id.
- `GET /v2/slots?eventTypeId&start&end&timeZone` — date-keyed `{ data: { "YYYY-MM-DD": [{start ISO}] } }`.
- `POST /v2/bookings` — body `{ start(UTC ISO), eventTypeId, attendee{name,email,timeZone,language}, metadata{notes,phone} }`; response `{ data: { id, uid, ... } }`.
