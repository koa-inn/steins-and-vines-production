# Phase 29.1 Plan 02: BrewPad UI for Batch Customer Reassignment

**One-liner:** BrewPad Change Customer control with type-ahead search, inline add-new form, confirm-gated Zoho push, and in-place DOM patch with zoho_warning toast support.

## What Was Built

### buildCustomerReassignUpdates pure helper (Task 1 — TDD)

A new top-level pure function in `js/brewpad.js` at the `buildRefreshUpdates` location that:
- Accepts `{ contact_id, contact_name|name, email, phone }` (type-ahead result or add-new form object)
- Reuses existing `splitCustomerName` for firstname/lastname derivation
- Always returns all six keys as strings: `customer_id, customer_name, customer_firstname, customer_lastname, customer_email, customer_phone`
- Exported in the `module.exports` block for test access

8 unit tests in `tests/frontend/brewpad-customer-reassign.test.js` cover: full contact_name, name field variant, single-token name, missing email/phone become `''`, absent contact_id becomes `''`, three-part name, and all-six-keys guarantee.

### Reassign control + customer search + inline add-new UI (Task 2)

New elements added to `js/brewpad.js`:
- **Module-level state:** `_reassignSearchTimer` (separate from `_soSearchTimer`), `_pendingReassign`
- **`fetchReassignSearch(term)`** — calls `GET {mwUrl()}/api/contacts/search?q=<term>` with `x-api-key` header; renders results with `escapeHTML` on all `contact_name`/`email`/`phone`; result click sets `_pendingReassign` and calls `submitReassign()`
- **HTML in `renderBatchDetail`** — rendered unconditionally after the SO search section:
  - `bp-reassign-btn` ("Change Customer") — toggles panel, always visible
  - `bp-reassign-panel` — hidden container with:
    - `bp-reassign-search-input` (400ms debounce via `_reassignSearchTimer`)
    - `bp-reassign-results` (type-ahead list)
    - `bp-reassign-dismiss` (Cancel button)
    - `bp-reassign-addnew-toggle` ("+ Add new customer" link)
    - `bp-reassign-addnew` form with `bp-reassign-new-name`, `bp-reassign-new-email`, `bp-reassign-new-phone`, `bp-reassign-new-save`
- **CSS** in `css/brewpad.css` under `/* Phase 29.1: Customer Reassign Control */`:
  - `.bp-reassign-panel`, `.bp-reassign-search-wrap`, `.bp-reassign-results`, `.bp-reassign-results:empty`, `.bp-reassign-addnew-toggle`, `.bp-reassign-addnew`

### Confirm-gated submit, DOM patch, warning handling, build (Task 3)

**`submitReassign()`** — module-level function:
- Reads `_pendingReassign`, `_currentBatchDetail` for batch_id, zoho_so_number, expectedVersion
- D-02/D-03: if `zoho_so_number` present → `showConfirmSheet(...)` then `doPost()`; absent → `doPost()` directly
- `doPost()` disables button (`Saving…`), POSTs to `POST /api/batch/reassign-customer` with `x-api-key`, `Content-Type: application/json`, body: `{ batch_id, zoho_so_number?, expectedVersion, customer }`
  - `customer: { contact_id }` for existing pick (skips middleware's Zoho contact resolution)
  - `customer: { name, email, phone }` for add-new (triggers middleware's lookup-or-create)
- **409 / version_conflict** → `showToast('Batch was updated elsewhere — please reload', 'error')` via `isVersionConflict`
- **Success path:**
  - `buildCustomerReassignUpdates(_pendingReassign)` to get updates object
  - Patch `_currentBatchDetail.last_updated` ← `data.new_version`
  - Patch `_currentBatchDetail` fields, `bp-detail-customer`/`bp-detail-email`/`bp-detail-phone` via `textContent`
  - Patch `_batchesData` + `_allBatchesData` by batch_id
  - `sessionStorage.removeItem('sv-bp-batch-' + batchId)`
  - `data.zoho_warning` → `showToast('Customer saved — Zoho not updated: ' + ...', 'warn')` (D-05)
  - Clean success → `showToast('Customer reassigned', 'success')`
  - Reset button, hide panel and add-new form, clear `_pendingReassign`
- **Build:** `npm run build` regenerated `js/brewpad.min.js`, `css/brewpad.min.css`, stamped `brewpad.html` (and all other HTML/JS build artifacts)
