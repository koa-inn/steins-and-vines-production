# Phase 29.1 Plan 01: Middleware Backend for Batch Customer Reassignment

**One-liner:** Zoho contact type-ahead search + batch-first customer reassignment with Apps Script optimistic lock and D-03/D-05 Zoho propagation semantics.

## What Was Built

Two new endpoints added to `zoho-middleware/routes/pos.js`:

### GET /api/contacts/search
- Auth guard (x-api-key header or query param)
- Minimum 2-character query validation
- Calls `zohoGet('/contacts', { search_text: q })` and maps results to slim objects `{ contact_id, contact_name, email, phone }`
- Reads email/phone from primary `contact_persons` entry with top-level field fallback
- 502 on Zoho error with no PII in log (T-29.1-03)
- 200 with `{ contacts: [] }` when Zoho returns no results (not an error)

### POST /api/batch/reassign-customer
- Auth guard (x-api-key)
- Validates `batch_id` and requires either `customer.name` or `customer.contact_id`
- **Contact resolution (Step 1):** if `contact_id` provided, use directly; else lookup by email → create via `buildContactPayload` → duplicate-name fallback to name search
- **Batch update (Step 2):** `axios.post(APPS_SCRIPT_URL, { action: 'update_batch', expectedVersion, updates: { customer_id, customer_name, customer_firstname, customer_lastname, customer_email, customer_phone } })`; 409 on `version_conflict`
- **Zoho push (Step 3, D-03):** only when `zoho_so_number` present; resolves internal doc ID via `zohoGet` with exact-match loop; `zohoPut` customer_id
- **D-05 handling:** Zoho PUT failure returns `{ ok: true, batch_updated: true, zoho_warning: '<message>' }` at HTTP 200 — batch change stands
- `eventLog.logEvent('batch.customer_reassigned', { batchId, newCustomerId, newCustomerName, zohoUpdated, zohoWarning })` — no email/phone (T-29.1-03)
