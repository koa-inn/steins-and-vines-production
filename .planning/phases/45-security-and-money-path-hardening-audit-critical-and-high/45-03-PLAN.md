<objective>
Implement the Redis-outage fail-closed policy (D-06/D-07/D-08): keep selling on a Redis blip by falling back to in-process (per-process MemoryStore) limits and locks instead of failing open. The middleware is a single Railway instance, so per-process == all traffic — nearly as safe as Redis (D-06). PIN brute-force throttling stays always-on (D-07). Fix the factually-wrong comments claiming a MemoryStore fallback already exists (D-08).

Purpose: Today `skip: redisUnavailableSkip` bypasses the rate-limit store entirely and `acquireLock` returns true (fail-open) on disconnect — so a Redis outage simultaneously removes PIN brute-force throttling AND double-charge protection, exactly when defenses matter most.
Output: server.js limiters that fall back to MemoryStore, an in-process lock fallback in cache.js, corrected comments, and a Redis-outage test.
</objective>
