API CONTRACT (Plans 07 and 12 depend on this exact shape):
POST /api/preorder/initialize
  body: {items:[{item_id:string, qty:int}], recaptcha_token:string}
  200: {checkoutToken, secretToken, invoice_number:'LR-'+16 hex, deposit_total:number, kit_count:int}
  400: {error} (basket invalid, reCAPTCHA failed) ; 502: {error:'Payment initialization failed'}
POST /api/preorder/deposit
  body: {transaction_id:string<=64, invoice_number:string, items:[{item_id, qty}], customer:{name<=100, email<=254, phone<=30}, consent:{accepted:true, text:string<=500}, newsletter:boolean, recaptcha_token:string}
  201: {ok:true, deposit_total, kit_count, salesorders:[{salesorder_id, salesorder_number, item_id, name, release_label}]}  (built in Plan 07)
  200: same body as a cached replay of a completed transaction
  4xx/5xx: {error:string, voided:boolean}
Redis keys: 'preorder:nonce:<invoice_number>' -> {amount, lines, created_at} TTL 3600; 'preorder:idem:<txn>' lock TTL 900 and final response cached 86400; 'preorder:pending:<txn>' sentinel (Plan 07).

Checkout replay suffixes: '', ':sv-cart-ferment', ':sv-cart-ingredients' (checkout.js l.247-258).
From lib/helcim.js: initializeCheckout(amount, currency, {invoiceNumber}) (Plan 03); getCardTransactionById(id) -> {status, transactionId, invoiceNumber, amount, type}.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/preorder/* | Fully untrusted public input (no API key) |
| middleware → Helcim | Readback is the source of truth for what was charged |
| middleware → Redis | Nonce and idempotency state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-100-25 | Tampering / DoS | void of someone else's charge (Pitfall 1, HIGH) | mitigate | Void only after readback.invoiceNumber equals the caller's 64-bit random nonce; ownership checked before lock so a forged request cannot hold the victim's lock |
| T-100-26 | Tampering | client-chosen amount | mitigate | Amount computed server-side at initialize and re-checked at deposit in integer cents against both basket and nonce record; no overpay tolerance |
| T-100-27 | Spoofing | cross-route txn reuse (Pitfall 2) | mitigate | assertTxnNotReplayed across '', ':sv-cart-ferment', ':sv-cart-ingredients', ':preorder'; type must be 'purchase' |
| T-100-28 | Tampering | basket swapped after payment | mitigate | Basket must equal the nonce record's lines |
| T-100-29 | Denial of service | bots / card testing | mitigate | reCAPTCHA v3 fail-closed in production at both routes; paymentLimiter on /api/preorder; Referer guard retained |
| T-100-30 | Repudiation | Zoho offline after charge (Pitfall 3) | mitigate | /preorder/deposit on OFFLINE_CAPABLE_POSTS; route voids and returns 503 {voided} |
| T-100-31 | Information disclosure | PII in logs | mitigate | Logs/events carry txnId, counts, totals only; test spies on logger + eventLog |
| T-100-32 | Elevation of privilege | keyless bypass too broad | mitigate | Exact-path entries in KEYLESS_POSTS; test proves an unrelated keyed POST still rejects |
| T-100-33a | Elevation of privilege | deposits taken on production before owner sign-off | mitigate | PREORDER_DEPOSITS_ENABLED kill switch on initialize (default off); only Plan 14 sets it on production |
| T-100-33 | Tampering | nonce reuse | mitigate | Nonce bound to one Helcim checkout; per-txn lock + replay marks; nonce deleted on success (Plan 07) |
</threat_model>
