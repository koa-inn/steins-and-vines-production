Create `zoho-middleware/lib/gift-card-pg.js` (CommonJS, ES5 style matching lib/*.js, 'use strict'). It never requires 'pg' and never creates a pool; every function receives the transaction `client`. All SQL uses $n placeholders only (ASVS V5). Pass money as strings formatted to 2 dp (validate first: finite, at most 2 decimal places by checking Math.round(x*100) equals x*100 within 1e-9, |x| <= 99999999.99) and convert numeric columns back with Number().

Write-op algorithm (redeem / reload / adjust), implementing the locked Stage-2 shape plus a row lock that resolves RESEARCH Pitfall 2 deterministically:
1. `select ... from gift_cards where cert_number = $1 for update` -> none: return not_found.
2. Replay check: `select cert_number, kind, ... from gift_card_transactions where tx_ref = $1`. If found and cert_number+kind match -> return ok with idempotent:true and the card's CURRENT balance/status (mirrors Phase 51's idempotent response). If found but cert or kind differ -> return tx_ref_conflict.
3. Business checks under the lock: redeem requires status 'active' and balance >= amount; reload rejects 'void'; adjust requires status 'active' (D-06 literal "active cards only") and balance + delta >= 0 else negative_balance (rejected, never clamped).
4. `insert into gift_card_transactions (...) values (...) on conflict (tx_ref) do nothing returning id` with balance_before/after computed from the locked row. Zero rows returned -> throw an Error with code 'GC_TXREF_RACE' (forces the caller's transaction to roll back).
5. Guarded update: `update gift_cards set current_balance = current_balance + $signedAmount, status = <rule>, last_updated = now() where cert_number = $1 and current_balance + $signedAmount >= 0 returning *`. rowCount !== 1 -> throw Error code 'GC_GUARD_FAILED'. Status rule: redeem/adjust result 0 -> 'depleted', otherwise 'active'.
Business rejections in step 1-3 happen before any write, so they RETURN {ok:false,...} (no throw). Only infrastructure faults and the two defence-in-depth guards throw.

issue: validate faceValue > 0 (missing_fields when absent/NaN, invalid_amount when bad precision); replay check by tx_ref first; then `insert into gift_cards ... on conflict (cert_number) do nothing returning *` -> no row: return duplicate; insert ledger row kind 'issue' amount +face; then bump the sequence when the numeric suffix exceeds it (`select setval('gift_card_cert_seq', $n) where $n > (select last_value from gift_card_cert_seq)` — runtime SQL, allowed outside migrations; D-14 "seed must account for overridden numbers").
voidCard: lock row; status not in ('active','depleted') -> invalid_status (status check BEFORE any replay logic so a double void matches Apps Script); set status 'void', void_reason, last_updated; insert ledger row kind 'void', amount 0, tx_ref 'void:' + certNumber, reason null, note = void reason (truncated 512).
updateInvoice: update zoho_invoice_number + last_updated; not_found when 0 rows; no ledger row (metadata only).
nextCertNumber: loop up to 50 times `select nextval('gift_card_cert_seq')`, format 'GC-' + 6-digit zero pad, return the first not present in gift_cards; throw after 50.
lookup: plain select, numerics to Number, issued_date as 'YYYY-MM-DD' string, last_updated as ISO string.
Every write result carries `_card` (post-op row) and `_ledger` (row written or matched, null for updateInvoice) for 84-05's copy-state mirror.
