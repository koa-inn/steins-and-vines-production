<objective>
Harden the BrewPad recipe editor's save path (D-05) so a failed save never orphans
in-progress work: register the recipe form in the existing `_formSavers` draft system,
correctly detect non-2xx failures, consume the D-03 `code`/`cause` contract to highlight the
offending line, and offer a retry on transient failures.

Purpose: The recipe editor is the ONLY major BrewPad form NOT protected by the session-draft
system, and `saveRecipe()` ignores HTTP status (parses `r.json()` without `r.ok`) — so a
422/502 can be misread as success and a session-expiry/reload silently loses the edits. D-03
(73-04) adds a NEW reason for saves to fail (422), so this failure-path hardening ships with it.

Output: draft-registered, status-aware, retry-capable `saveRecipe`; rebuilt `brewpad.min.js`;
frontend regression tests.
</objective>
