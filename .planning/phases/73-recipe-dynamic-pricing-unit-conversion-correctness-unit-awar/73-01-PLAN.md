<objective>
Create the ONE shared unit-aware ingredient-cost helper and wire the two aggregate
sum-sites that live inside `recipe-scaling.js` to it. This is the foundation every
downstream sum-site (recipes.js read path, pos-recipe.js sale path) consumes.

Purpose: The bug is divergence — four+ hand-rolled `Σ(rate × quantity)` loops with no
unit conversion. Consolidating to one pure helper that converts `line.unit` → `item.unit`
(or fails closed) is the entire fix strategy (D-01/D-02). This plan delivers the helper +
the in-file wiring; other plans wire the remaining route-level sum-sites.

Output: `ingredientLineCost(item, line)` + `classifyUnit(raw)` in `lib/recipe-scaling.js`,
consumed by `computeScaledRecipeTotal` and `computeModifiedRecipeTotal`, with regression
tests and completed test fixtures.
</objective>

<interfaces>
<!-- Pinned contract this phase depends on. All downstream plans consume these exact shapes. -->
Helper signatures (add to zoho-middleware/lib/recipe-scaling.js, pure, no I/O, no new requires):
  classifyUnit(raw) -> { family: 'mass'|'volume'|'count'|null, norm: <lowercased-trimmed-unit> }
  ingredientLineCost(item, line) -> { ok: true, convertedQty: <number>, cost: <number> }
                                  |  { ok: false, error: <string naming the line> }

Conversion families (D-02 scope):
  MASS:   { kg: 1, g: 0.001 }                 (g↔kg via ÷/×1000)
  VOLUME: { l: 1, ml: 0.001 }                 (ml↔L via ÷/×1000)
  COUNT:  ['pcs','ea','each','unit','pkg','pack']  (pass-through, no numeric conversion)
  Cross-family or unknown family on either side => { ok: false } (fail closed).
  D-06 imperial (oz/lb/tsp/tbsp) is added ONLY if Task 1's audit finds live usage.

Fail-closed error string (mirror Phase 67 name-the-item precedent):
  'Cannot price "<item_name|item_id>": recipe unit "<line.unit>" is not convertible to item unit "<item.unit>"'

Security invariant to preserve (T-36-01): rate is ALWAYS read from `item.rate` (server
catalog entry), NEVER from the client/recipe-supplied `line` object.

Aggregate fail-closed propagation: when a line is unpriceable, computeScaledRecipeTotal /
computeModifiedRecipeTotal THROW a typed error (an Error whose `.name === 'RecipeLineUnitError'`
and `.message` = the fail-closed string above). Callers translate the throw into the
appropriate HTTP response in later plans. Do NOT change these functions' happy-path numeric
return; do NOT let them return NaN/0 on failure.
</interfaces>
