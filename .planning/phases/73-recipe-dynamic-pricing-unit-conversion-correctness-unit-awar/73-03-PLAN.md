<objective>
Wire the CRITICAL sale/stock sum-site — `_runRecipeConfirm`'s invoice `lineItems` build in
`routes/pos-recipe.js` — plus the kiosk quote's display `line_total`, to the shared helper,
so the Zoho invoice + real inventory deduction use the CONVERTED quantity and match the quote.

Purpose: This is the money-and-stock half of the bug. `pos-recipe.js` independently re-reads
`catalogEntry.rate` and sends the raw (scaled-but-unconverted) quantity as the Zoho invoice
line `quantity` with NO per-line unit override — so Zoho decrements stock by that raw number.
Fixing only the display path (73-02) leaves the actual charge + stock draw-down wrong
(RESEARCH Pitfall 1). Fail-closed here is tiered: refuse BEFORE charge (quote/pre-sale 422);
post-charge is defense-in-depth → void, mirroring the existing void-on-invoice-failure block.

Output: sum-site 5 + quote line_total converted; tiered fail-closed; quote==sale, converted
stock draw-down, discount-on-converted, and void-on-unpriceable regression tests; completed fixtures.
</objective>

| T-73-03 | Information disclosure | 422/void error strings | mitigate | Error names only item name + units; no rate/tax/catalog internals |
| T-73-SC | Tampering | npm installs | accept | No package installs this phase |
