<objective>
Add save-time unit validation (D-03) to `POST /api/recipes` and `PUT /api/recipes/:id` in
`routes/recipes.js`, rejecting an un-convertible unit/rate mismatch BEFORE proxying to Apps
Script, and add the machine-readable `code`/`cause` fields (D-05c) that the BrewPad editor
(73-05) consumes to preserve the draft + highlight the offending line.

Purpose: Closes the write-time loop so an un-priceable recipe can't be saved as sellable
(AC-05). Apps Script has NO Zoho catalog access, so this validation MUST live in the
middleware — the only tier holding both the recipe payload and the catalog at write time
(RESEARCH Pitfall 4). Also catches the invalid `L`-on-a-count Whirlfloc line (D-01 code side).

Output: async pre-flight validation on both write routes returning `422 { error, code, cause }`
before `callAppsScriptPost`; D-03 reject tests proving no partial write.
</objective>

PINNED save-error contract (73-05 depends on this EXACT shape — do not diverge):
  Unit mismatch reject:
    res.status(422).json({
      error: 'Cannot save recipe: "<item>" unit "<X>" is not convertible to catalog unit "<Y>"',
      code:  'unit_mismatch',
      cause: <offending item_name or item_id>
    })
  Also add a `code` to the existing PUT activation-guardrail 422s (D-05c consistency):
    locked_price<=0  -> code:'activation_locked_price'
    ingredient_count<1 -> code:'activation_no_ingredients'
  Existing 502/'save failed' bodies: add code:'save_failed'. Keep the human `error` string
  on every body (73-05 falls back to it when code/cause absent).

D-03 placement: read cache.get(C.CACHE_KEYS.INGREDIENTS_ALL), build the item_id→item map
  (same idiom as enrichWithComputedPrice), run each incoming ingredient line through
  classifyUnit/ingredientLineCost, and return the 422 above on the FIRST non-convertible line —
  BEFORE callAppsScriptPost('create_recipe'/'update_recipe', ...). Because cache.get is async,
  this must be a `.then()` chain (the existing D-02 guardrail is synchronous — the new check
  wraps/precedes the callAppsScriptPost call in the promise chain).
</interfaces>
