## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Staff browser -> Apps Script doPost | Staff-authenticated CRUD calls cross from browser to server |
| Middleware -> Apps Script doPost (server_token) | Server-to-server calls use shared secret |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Spoofing | doPost create_recipe (staff) | mitigate | `checkAuthorization(e)` validates Google OAuth token before dispatching to staff CRUD cases -- recipe actions are inside the staff-auth block, not the unauthenticated block |
| T-12-02 | Spoofing | doPost create_recipe (server_token) | mitigate | Server token validated against `PropertiesService.getScriptProperties().getProperty('SERVER_WRITE_TOKEN')` with constant-time comparison before dispatching to server_token actions |
| T-12-03 | Tampering | createRecipe / updateRecipe input | mitigate | All string fields pass through `sanitizeInput()` which strips script tags, event handlers, and javascript: URLs. Numeric fields validated with `Number()`. Invalid JSON in ingredients returns error response. |
| T-12-04 | Injection | Recipe name / description / notes | mitigate | `sanitizeInput()` strips XSS vectors before writing to Google Sheets cells. No raw HTML rendering -- data is always sanitized on write. |
| T-12-05 | Denial of Service | Concurrent createRecipe calls | mitigate | `acquireScriptLock(15000)` serializes recipe creation to prevent duplicate ID generation from concurrent requests |
| T-12-06 | Elevation of Privilege | Unauthenticated recipe creation | mitigate | Recipe CRUD cases are placed inside the staff-auth switch block (after `checkAuthorization(e)` passes) -- not accessible without valid OAuth credentials |
</threat_model>
