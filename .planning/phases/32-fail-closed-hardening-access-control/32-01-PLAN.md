Make the money path's reCAPTCHA verification and BOTH Redis-down duplicate-order guards fail CLOSED in production. Today all three fail OPEN: `verifyRecaptcha()` returns `{success:true}` when the key is unset and on timeout; `checkTransactionIdAndProceed()` calls `runCheckout()` in its Redis-down catch; and the idempotency-key catch (`checkout.js:~138`) calls `processCheckout()` again in its Redis-down catch.

The phase GOAL says duplicate charges when Redis is down "are all rejected" — so BOTH the transactionId guard AND the sibling idempotency-key catch (which can otherwise permit a second `processCheckout()` for the same charge) must fail closed with 409 in prod. Dev/CI (NODE_ENV unset) must stay fail-open so local development is unaffected (D-01).

Output: HARDEN-01 (reCAPTCHA fail-closed) and HARDEN-03 (replay-guard 409 + idempotency-key catch 409) closed, with the Phase 31 test.todo markers converted to real prod-path assertions.
