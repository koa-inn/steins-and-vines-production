<objective>
Close two access-control gaps:
- **PII-01**: Four PII-exposing GET routes (`/api/contacts`, `/api/invoices`, `/api/items/inspect`, `/api/snapshot`) are currently reachable without the API key because the global guard exempts ALL GET (`server.js:254`) — and the Referer guard can be satisfied by the public site. Add a TARGETED key requirement on exactly those 4 paths (D-07) — NOT a global GET-bypass inversion (high blast radius: ~12+ GET routes are legitimately public).
- **PII-02**: Mutating routes forward raw `req.body` to Zoho (`POST /api/items`, `PUT /api/inventory/items/:id`) or read it loosely (`POST /api/taxes/apply`). Add a shared whitelist body validator (D-08) that rejects missing/malformed required fields with 400 BEFORE any Zoho call and strips unknown fields (no field smuggling). `POST /api/admin/upload-catalog` already validates its shape — confirm/light-touch.

Purpose: Stop PII leaking to unauthenticated callers and stop unvetted fields reaching Zoho — without breaking the legitimately-public storefront/booking/kiosk GET routes.

Output: PII-01 and PII-02 closed.
</objective>
