<objective>
Convert validateEnv.js from a silent-fail-open config into a loud-fail-closed boot gate (HARDEN-04 + D-02/D-06). Today GP_* (Global Payments — dead) vars are checked while the live secrets that actually gate the money path (HELCIM_WEBHOOK_SECRET, REDIS_ENCRYPTION_KEY) are missing or only OPTIONAL, and there is no NODE_ENV/platform assertion — so a deploy can silently run with NODE_ENV unset (which would disable every fail-closed gate added in Plans 01-02).

Purpose: Defense in depth. The runtime gates (D-03/D-04/D-05 in Plans 01-02) fail closed at request time; this plan makes a misconfigured prod deploy fail LOUDLY at boot instead — so a missing secret breaks the deploy, not every customer, and an accidental NODE_ENV-unset deploy cannot silently re-open all the gates.

Output: HARDEN-04 closed. NOTE: a human action (set NODE_ENV=production + confirm prod secrets in Railway) is required for the boot gate to have teeth — see user_setup.
</objective>
