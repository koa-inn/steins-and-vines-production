<objective>
Make Helcim and Cal.com webhook signature verification fail CLOSED in production when the signing secret is unset, and reject the unsigned/forged event with HTTP **403** (the ROADMAP criterion 2 status). Today both `lib/helcim.js#verifyWebhookSignature` and `lib/calcom.js#verifyWebhook` return `true` (skip verification) when the secret is missing — meaning an unsigned/forged webhook is accepted — and the two consume sites in `routes/webhooks.js` reject with 401. Webhooks are exempt from the API-key guard (`server.js:260`) and have no Referer, so HMAC is their ONLY auth.

Purpose: An attacker who knows a webhook URL must not be able to inject a forged payment/booking event when the secret happens to be unset in prod. Dev (NODE_ENV unset) keeps the skip-verification warning path so local webhook testing is unaffected (D-01/D-04). The rejection status is changed 401 -> 403 to match ROADMAP criterion 2 ("400/403") verbatim — the criterion lists these codes as non-negotiable acceptance gates.

Output: HARDEN-02 closed for both webhook verifiers; the route consume sites return 403; the Phase 31 HARDEN-02 test.todo markers converted to real prod-path assertions.
</objective>
