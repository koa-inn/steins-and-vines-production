<objective>
Make Helcim and Cal.com webhook signature verification fail CLOSED in production when the signing secret is unset. Today both `lib/helcim.js#verifyWebhookSignature` and `lib/calcom.js#verifyWebhook` return `true` (skip verification) when the secret is missing — meaning an unsigned/forged webhook is accepted. Webhooks are exempt from the API-key guard (`server.js:260`) and have no Referer, so HMAC is their ONLY auth.

Purpose: An attacker who knows a webhook URL must not be able to inject a forged payment/booking event when the secret happens to be unset in prod. Dev (NODE_ENV unset) keeps the skip-verification warning path so local webhook testing is unaffected (D-01/D-04).

Output: HARDEN-02 closed for both webhook verifiers; the Phase 31 HARDEN-02 test.todo markers converted to real prod-path assertions.
</objective>
