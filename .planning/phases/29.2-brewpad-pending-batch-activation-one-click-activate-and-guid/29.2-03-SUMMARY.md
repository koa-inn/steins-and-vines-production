## What Was Built

**Guided-sheet contract tests** — appended as `describe('schedule & activate guided sheet', ...)` to `tests/frontend/brewpad-activation.test.js` without modifying earlier blocks:
- Pins the 9 `bp-sa-*` id constants (Pitfall 5 guard — no `bp-create-sheet` collision)
- Asserts all three step1Done routing branches: `version_conflict`, `partial`, `failed` (T-29.2-10)
- XSS guard: `escapeHTML('<script>...')` contains no raw `<` (T-29.2-09)
- `todayPacific()` format pin (sheet start-date default source)

**`buildScheduleActivateSheetHtml(batch)`** — returns the inner HTML string for the sheet form:
- Heading with `escapeHTML(batch.batch_id)` and `escapeHTML(batch.product_name)`
- Schedule `<select id="bp-sa-schedule-select">` populated from `_fermSchedules`
- `<div id="bp-sa-schedule-preview">` for step-by-step preview
- `<input type="date" id="bp-sa-start-date">` defaulting to `todayPacific()`
- Vessel search (`bp-sa-vessel-search` / `bp-sa-vessel-dropdown` / `bp-sa-vessel`)
- Shelf (`bp-sa-shelf`) and Bin (`bp-sa-bin`) inputs
- `<button id="bp-sa-submit">Schedule &amp; Activate</button>`
- Every interpolated field via `escapeHTML(... || '')`

**`openScheduleActivateSheet(batch)`** — named function declaration inside the IIFE (hoists above 29.2-02 call site):
1. `_fermSchedules` guard: if empty, calls `reloadSchedules()` and defers `_buildAndShow`; handles both promise and fire-and-forget variants
2. Dynamic sheet creation: `getElementById('bp-sa-sheet') || createElement('div')`, class `bp-create-sheet`, appended to body
3. Open lifecycle: display toggle + `bp-create-sheet--open` class on `setTimeout(10)`, backdrop-click-to-close, focus first input at 260ms
4. Schedule select `change` handler: finds schedule in `_fermSchedules`, parses `steps_parsed || JSON.parse(steps)`, renders step preview with Transfer/Packaging badges, every field via `escapeHTML`
5. `bindVesselSearch` / `bindShelfInput` / `bindBinInput` wired to `bp-sa-*` elements
6. Submit handler: reads schedule (required — bails with toast if none selected), reads `bp-sa-start-date` (falls back to `todayPacific()`), builds `batchUpdates = { status:'primary', start_date, [vessel_id, shelf_id, bin_id] when set }`, runs two-step step1Done orchestration

**Two-step step1Done orchestration** (copied verbatim from admin.js:7379-7424):
- Step 1: `adminApiPost('update_batch', { batch_id, expectedVersion: batch.last_updated, updates: batchUpdates })`
- On step1 success: `step1Done = true`; `newVersion = step1Result.newVersion || batch.last_updated`
- Step 2: `adminApiPost('update_batch_schedule', { batch_id, expectedVersion: newVersion, schedule_snapshot: schedSteps })`
- Full success: `'Batch activated with N task(s) scheduled'` toast + `closeScheduleActivateSheet()` + cache-bust block + `loadDashboard()`
- Partial (`step1Done` = true, step2 failed): `'Batch activated, but the schedule didn't save — assign it from the batch detail'` warning + sheet close + cache-bust + refresh (batch NOT left pending)
- Version conflict (!step1Done): `'Version conflict — refresh and try again'` error toast
- Generic failure: `'Failed: msg'` error toast; always re-enables `submitBtn`

**`closeScheduleActivateSheet()`** — mirrors `closeCreateSheet`: removes `bp-create-sheet--open`, hides on `setTimeout(180)`, no-op if absent.

**Detail pane footer buttons (Task 3)**:
- Markup: `#bp-activate-detail-btn` and `#bp-sa-detail-btn` emitted inside `bp-detail-actions` only when `statusKey === 'pending'`; existing `#bp-bottling-invite-btn` (gated on `b.customer_email`) and `#bp-delete-batch-btn` preserved and unchanged
- `#bp-activate-detail-btn` binding: `showConfirmSheet` → `adminApiPost('update_batch', { status:'primary', start_date: todayPacific(), expectedVersion: b.last_updated })` → on success: update `b.status`, update both `_batchesData`/`_allBatchesData` caches, reset `_batchesLoaded`/`_dashLoadTime`, remove sessionStorage entry, `renderBatchDetail(b)` + `renderBatchList()`; on error: toast + re-enable button
- `#bp-sa-detail-btn` binding: `openScheduleActivateSheet(b)` (resolves 29.2-02 forward reference)
