  if (titleEl) titleEl.textContent = title;
  if (msgEl) msgEl.textContent = msg;

  if (detailEl) {
    if (extra && extra.txnId) {
      detailEl.textContent = 'Ref: ' + extra.txnId;
      detailEl.style.display = '';
    } else {
      detailEl.style.display = 'none';
    }

    retryBtn.style.display = canRetry ? '' : 'none';
    retryBtn.onclick = function () {
      kioskShowView('browse');
      kioskStartCheckout();
    };

  if (backBtn) {

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Information Disclosure | kiosk.js error display | mitigate | Only display transaction ID (opaque reference string). No internal error messages, Zoho details, or stack traces shown to user. The `txnId` is already known to the card terminal and is safe to display. |
| T-02-07 | Spoofing | kiosk.js payment_voided check | accept | Frontend displays void status from trusted backend response. An attacker would need to MITM the localhost/Railway connection (protected by HTTPS in production). Low risk: kiosk is staff-only on a controlled network. |
| T-02-08 | Tampering | kioskLoadProducts(true) bypass | accept | If staff navigates away without tapping Done, stock refresh skips but server-side cache was already busted (Plan 01 Task 2). Next product load fetches fresh data. No financial impact. |
</threat_model>
