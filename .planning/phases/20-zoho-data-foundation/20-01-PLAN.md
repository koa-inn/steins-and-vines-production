Immediately after fetching all items via fetchAllItems, pick the first item and call zohoApi.inventoryGet('/items/' + firstItem.item_id) to get the full item with custom_fields array. Log all CF labels found on that item: log('[preflight] Custom fields on ' + firstItem.name + ': ' + labels.join(', ')). Then check if any CF label exactly matches 'Subcategory' (case-sensitive). If no match found, log an error: '[preflight] ABORT: No custom field with label "Subcategory" found. Available labels: ' + labels.join(', ') + '. Create the CF in Zoho first (Settings > Preferences > Items > Custom Fields).' and call process.exit(1). If the label exists, log '[preflight] Confirmed: "Subcategory" custom field exists' and proceed with tagging. This pre-flight check prevents 200+ silent no-op PUT calls if the CF label is wrong.

    Per D-05, implement keyword-based classification with a RULES array ordered to avoid false positives (per RESEARCH.md pitfall 5 and 6):
    1. Hops (mosaic, citra, saaz, hallertau, simcoe, fuggle, golding, nugget, magnum, northern brewer, saphir, spalter, melon, idaho, el dorado, wai-iti, krush, strata, sabro, motueka, amarillo, falconer, cryo)

    7. Packaging (bottle, cork, crown cap, bung, beverage bag, swing-top, bordeaux) — exclude items already matched as Equipment (capper, brush, filler wand)

    The guessSubcategory(item) function takes an item object, lowercases item.name, and iterates RULES in order — first keyword match wins.

    Main flow:
    1. Load dotenv from parent .env — require('dotenv').config({ path: require('path').join(__dirname, '..', '.env') })
    2. Require zoho-api directly (no running middleware needed)
    3. Call zohoApi.fetchAllItems({ status: 'active' }) to get all items with item_id
    4. Run pre-flight CF label inspection on first item (see above)
    5. Filter to ingredients only: exclude product_type === 'service', exclude items where cf_type (lowercased) is in KIT_CATEGORIES (wine, beer, cider, seltzer)
    6. For each ingredient, call guessSubcategory. If result is non-null, add to toTag array. If null, add to ambiguous array.
    7. Per D-04 correction (RESEARCH.md pitfall 3): include ALL hops items in the tagging run — even those with Zoho native category "Hops" — because the Subcategory custom field may not be set.
    8. Skip items that already have a subcategory CF value set (check item.custom_fields for a field with label Subcategory and non-empty value). Log as "[skip] already tagged".
    9. In dry-run mode: log WOULD TAG for each item, do not call inventoryPut.
    10. In live mode: call zohoApi.inventoryPut('/items/' + item.item_id, { custom_fields: [{ label: 'Subcategory', value: subcategory }] }) with 700ms delay between calls. Wrap in try/catch, collect errors, continue.
    11. Print summary: Total ingredients, Auto-tagged, Skipped (already tagged), Errors, then the manual review list with SKU and item name for each ambiguous item.

    Per D-07, the summary section for ambiguous items should print a clear header "MANUAL REVIEW REQUIRED" with item count, SKU, and name for each.

    Per D-07, the script must count items per subcategory, flag items with empty subcategory, and report coverage percentage.

    File structure follows the export-snapshot.js pattern exactly (JSDoc header with Prerequisites and Usage, use strict, stdlib-only imports, MIDDLEWARE_URL constant, http.get with body accumulation, status code check, JSON parse with try/catch, .on('error') handler with "start the middleware" message).

    Per D-08 and RESEARCH.md Pattern 3, the script calls /api/ingredients (not /api/snapshot) to verify the full pipeline end-to-end — Zoho item -> flattenCF() -> shaped output includes subcategory.

    Script flow:
    1. No dotenv needed — this script only uses http (stdlib)
    2. MIDDLEWARE_URL from process.env.MIDDLEWARE_URL or default http://localhost:3001
    3. http.get to MIDDLEWARE_URL + '/api/ingredients'
    4. Check res.statusCode === 200, else log error and exit 1
    5. Accumulate body, parse JSON
    6. Extract items array from parsed.items (or empty array)
    7. Guard: if items.length === 0, warn cache may be warming, exit 1
    8. Iterate items: for each, read (item.subcategory || '').trim(). If empty, push to missing array. Otherwise, increment counts[subcategory].
    9. Print coverage report: Total ingredients count, Tagged count (total - missing), Missing count, Coverage percentage (rounded)
    10. Print breakdown: each subcategory name sorted alphabetically with count
    11. If missing.length > 0: print "Items Still Missing Subcategory" section with SKU and name for each, then process.exit(1)
    12. If missing.length === 0: print "All items tagged" confirmation, then process.exit(0)

    The .on('error') handler must print: "[verify-subcategories] ERROR: Could not reach middleware at " + MIDDLEWARE_URL, then "Start the middleware: node zoho-middleware/server.js", then process.exit(1).

    Log prefix: [verify-subcategories].
