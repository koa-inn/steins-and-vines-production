<objective>
Close audit finding **H1 / SEC-01**: the internal `.planning/` tree and `AUDIT-2026-06-29.md` are
served publicly on staging (verified HTTP 200), handing out the admin key + a file:line exploit map.
Root cause: a tracked root `.nojekyll` (added 2026-06-25 to serve `.well-known/security.txt`) disables
Jekyll on staging's classic branch-based Pages, nullifying the `_config.yml exclude: .planning/`. Chosen
fix (owner, 2026-07-03): **Option B — workflow strip.** Switch staging to an Actions-based Pages deploy
that strips `.planning/` + audit docs before publishing, mirroring prod's `deploy-production.yml`. This
keeps raw (no-Jekyll) serving — no risk of Jekyll mangling inline JS/JSON-LD — and `.well-known` keeps
serving because `upload-pages-artifact` auto-injects `.nojekyll`.

GSD keeps `.planning/` **tracked** (D-01) — the fix is about not SERVING it, never untracking it. The
leaked key itself is neutralized separately by the Phase 46 rotation; this phase removes the exploit map.
</objective>
