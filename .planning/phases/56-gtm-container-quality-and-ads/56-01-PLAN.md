## T1 — Environment split: keep staging OUT of the prod GA4 property (DO FIRST)

**Why first:** GTM `GTM-NHRCGLC5` + GA4 `G-WDYSXCM703` are shared staging↔prod, so every staging
event (incl. the Phase 55 `purchase` test order) lands in prod GA4. See
`.planning/todos/pending/ga4-staging-pollutes-prod-property.md`.

**Recommended: GA4 internal-traffic data filter (keeps DebugView working for the UAT).**
1. GA4 → Admin → Data Streams → the web stream → Configure tag settings → Show all → **Define
   internal traffic** → Create: `traffic_type = internal` when **Hostname** contains
   `staging.steinsandvines.ca`.
2. GA4 → Admin → **Data filters** → the "Internal Traffic" filter → set state to **Active**
   (Exclude). This drops staging from standard reports but **DebugView still shows staging events**
   — so the Phase 55 purchase UAT can be verified there.
3. Verify: load staging, confirm your events appear in **DebugView** but NOT in Realtime for the
   prod audience (give it a few minutes).

> Do NOT use a GTM "block all tags on staging hostname" trigger exception as the primary fix — it
> would also block DebugView, defeating the Phase 55 UAT. (A GTM hostname exception is a fine
> ADDITIONAL belt-and-suspenders for the purchase tag only, if desired, but leave DebugView a path.)

**Clean up the verification test data:** in GA4 DebugView/Realtime, check for the two test
purchases from Phase 55 verification — `SO-TEST-DEDUP-001` ($25) and `SO-TEST-OTHER-002` ($10).
GA4 can't delete events; if they landed, they'll age out of Realtime and the internal-traffic
filter prevents recurrence. Note them so they aren't mistaken for real revenue.
