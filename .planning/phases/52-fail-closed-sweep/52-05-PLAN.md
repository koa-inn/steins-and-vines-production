<interfaces>
Auth idiom (PATTERNS.md Pattern B) — lib/authTiers.requireTiers:
- `authTiers.requireTiers(['legacy','session'])(req, res, function(){ ...handler... })` — invoke INLINE inside the handler (never as a 3rd router.get arg).
- The global guard in server.js exempts every GET; these routes re-arm auth in-handler.
- `requireTiers` returns SYNC 401 when NO credential header/cookie is present; 403 when a tier is present but insufficient or resolveTier rejects (fail closed).
- resolveTier grants 'device' purely on a valid `x-device-token` header — it does NOT depend on KIOSK_ROUTES membership, so device-tier works on the availability route without editing KIOSK_ROUTES.

Cache idiom (PATTERNS.md Pattern C) — lib/cache.get/set/del already fail SOFT (resolve null on Redis-down):
- recipes.js:270-302 (get_recipe) is the read-through model: `cache.get(key) → hit ? res.json : callAppsScriptPost(...).then(cache.set(key, result, TTL))`. `RECIPES_CACHE_TTL = 600`.
- catalog.js:801-803 shows the bust toggle: `bustCache ? cache.del(KEY).then(()=>null) : cache.get(KEY)`.

M7 target — catalog.js:801-803, GET /api/kiosk/products, `var bustCache = req.query.bust === '1';`. Gate ONLY the bust branch; leave the cached read public. Tier: `['legacy','session']` (admin-grade — a kiosk device should not force a cold Zoho refetch; matches the /api/orders/recent precedent).

M8 targets:
