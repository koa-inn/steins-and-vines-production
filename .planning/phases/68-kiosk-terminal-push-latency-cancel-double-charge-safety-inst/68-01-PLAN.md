<objective>
Instrument the kiosk card-present sale path so the reported "reader isn't picking up" latency is CAPTURED from a real slow case instead of guessed. Two observation-only changes:

1. Server: emit per-stage timing across `/api/kiosk/sale` (`processSale`/`processSaleWithPrices`) via the existing `eventLog.logEvent('kiosk.*', …)` channel — lock acquired, catalog read (recording HIT vs cold-cache `rebuildKioskCatalog`), pre-charge assertion done, gift-card balance lookup duration, `terminalPurchase` sent, 202 returned. The cold-cache rebuild and the up-to-12s gift-card lookup are the two prime suspects; the timings must make it unambiguous which one dominates a slow case.
2. Client: measure wall-time from the moment the terminal prompt is shown (`_kioskPushToTerminal`) to the 202 response, and report it via a NEW fire-and-forget beacon to a NEW sink route — never overloading the pinned `_kcReportClientError`/`/api/kiosk/client-error` shape.

Purpose: turn an intermittent field complaint into a measured bottleneck so the follow-up latency-reduction phase targets the proven stage. This plan changes NO pipeline ordering or money movement — it only observes.
Output: instrumented `pos.js` + `kiosk-core.js` (+ rebuilt min), new telemetry regression tests.
</objective>

Design decisions locked (from CONTEXT + PATTERNS):
- Server stage timing uses `eventLog.logEvent('kiosk.sale_stage_timing', {...})` (or per-stage names under the `kiosk.` convention), each paired with a `log.info` line, at the natural markers already in pos.js (~327 lock, ~414-452 catalog + 429 rebuild branch, ~608 assertion, ~662-687 gc-lookup, ~726 terminalPurchase, ~750 202). Use `Date.now()` deltas from a request-start stamp. NO new logging module; NO PII.
- Client latency uses a NEW sibling function `_kcReportTerminalPushLatency` posting to a NEW route `/api/kiosk/telemetry`, which is a no-side-effect sink mirroring `/api/kiosk/client-error` (register it in the KIOSK_ROUTES/auth allowlist the same way) and emits `eventLog.logEvent('kiosk.terminal_push_latency', {...})`. Do NOT extend `/api/kiosk/client-error` or `_kcReportClientError` — that keeps `tests/frontend/kiosk-client-error-beacon.test.js` untouched.
- The `/api/kiosk/telemetry` route MUST be a bounded, validated sink: accept only a small numeric/duration + stage-name + refNumber payload, clamp/slice like the client-error route does, never trigger side effects, never echo PII.
</context>
