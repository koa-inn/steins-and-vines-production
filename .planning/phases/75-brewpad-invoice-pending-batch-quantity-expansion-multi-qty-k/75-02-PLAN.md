<objective>
Implement D-03: show a per-unit "Unit X of N" label on each pending batch that belongs to a multi-unit invoice line, so staff can track and activate the units of a qty>1 kit distinctly (e.g. "Italy Nebbiolo Style — Unit 1 of 3 / 2 of 3 / 3 of 3").

No new backend field and no schema change are needed (research finding): the ordinal is derived purely at render time from the existing sequential `batch_id`. Group the already-fetched batch list by `(zoho_so_number, product_sku)`, sort ascending by `batch_id`, and the ordinal is the batch's position in that group; N is the group size. Groups of size 1 render no label.

Purpose: staff can visually distinguish the N pending units created by Plan 01's backend fix.
Output: a `computeUnitLabel` pure helper (test-first), wired into both the card and table batch-list views, plus the regenerated `js/brewpad.min.js` bundle and re-stamped `brewpad.html`.

Note: this plan is independent of Plan 01 (no shared files; the label derives from `batch_id` client-side, needing no new backend field), so it runs in parallel. Live visual confirmation of the label depends on real multi-unit batches existing (Plan 01 deployed + INV-000171 backfilled via the revised-D-01 one-time manual re-import) and is an owner follow-up, not an in-plan checkpoint.
</objective>
