<objective>
Close the two documented VERIFICATION gaps for Phase 27 batch activation:

- **WR-01 (WARNING, BATCH-02):** Both one-click Activate handlers send `updates: { status: 'primary' }` with no `start_date`. The confirmation copy promises the start date is "set to today," but the backend `fermentation_started_at` priority chain (`updates.fermentation_started_at > updates.start_date > current.start_date > now`) stamps any pre-existing `current.start_date` instead of today. Fix: add `start_date: todayPacific()` to BOTH one-click activate payloads.
- **CR-01 (BLOCKER, BATCH-03):** The guided Schedule & Activate two-step orchestration (`update_batch` then `update_batch_schedule`) cannot distinguish a step-2 version conflict from a step-1 failure. A step-2 "Batch was modified" error is misrouted to the retry-conflict toast even though step 1 already committed, leaving the batch primary-with-no-schedule and no recovery UI. Fix: add a `step1Done` flag and reorder the catch to branch on it before matching error-message substrings.

Purpose: BATCH-02 and BATCH-03 are currently PARTIALLY SATISFIED. These fixes complete them so the confirmation-copy promise holds and the guided partial-failure path reports truthfully without stranding the batch.

Output: Edited `js/admin.js`, rebuilt `js/admin.min.js` (+ stamped `css/admin.min.css`), green test suite, clean lint.
</objective>
