<objective>
Land the middleware half of the kiosk quote≠charge fix. Two server changes, both backward-compatible with the currently-deployed kiosk JS so this plan can deploy to prod BEFORE the frontend (67-02):

1. Remove the silent 5% tax guess in `computeTax` — an unresolvable catalog tax becomes a fail-closed 400 naming the item (matches the Phase 52 fail-closed money-path doctrine).
2. Add a pre-charge assertion — when the client sends its displayed grand total, the server compares it to its own computed `grandTotal` before charging Helcim and rejects any divergence beyond $0.01. Server-computed totals remain the ONLY source of financial truth; the client value is asserted against, never trusted for pricing.

Purpose: make any client/server total divergence LOUD (fail-closed) instead of silently under-charging the displayed quote, and stop guessing tax rates.
Output: hardened `zoho-middleware/routes/pos.js` + updated/new middleware regression tests. This plan is the deploy-first unit; the frontend (67-02) only starts sending the asserted field after this ships.
</objective>

  client_grand_total : number   // the kiosk's displayed grand total (totals.total)

The server ASSERTS on client_grand_total only (compares to its computed grandTotal, tolerance $0.01).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| kiosk client → POST /api/kiosk/sale | Untrusted client-displayed totals (client_grand_total/client_tax_total) and item ids cross here; server anchors all pricing to the Redis catalog. |
| middleware → Helcim terminal | Money movement; must not occur if totals diverge or tax is unresolved. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-67-01 | Tampering | client_grand_total in sale body | mitigate | Assertion is a divergence DETECTOR only; server-computed grandTotal (catalog-anchored) remains the sole charge basis — a forged matching total cannot raise or lower the charge, only allow it to proceed at the server's own price. |
| T-67-02 | Spoofing (old client) | absent client_grand_total (back-compat) | accept | Old cached kiosk JS omits the field → assertion skipped by design; residual divergence exposure is transitional and reduced by catalog freshness (67-02). Owner-accepted per CONTEXT deploy-ordering decision. |
| T-67-03 | Denial of Service (self-inflicted) | computeTax fail-closed on unresolved tax | mitigate | Only genuinely unresolvable tax (no pct, no rule, no tax_id) fails; real 0% rates (rule 109900000000033411, zero-rated ingredients, gift certs, exempt custom lines) stay valid so legitimate sales are never blocked. Error names the item so staff can act. |
| T-67-04 | Information disclosure | assertion mismatch response | mitigate | Response copy is staff-actionable ("Totals changed — refresh…") and does not echo the server-computed grandTotal to the client. |
| T-67-05 | Elevation / replay | idempotency lock on mismatch reject | mitigate | Mismatch is a safe-to-retry rejection → lock released via WR-03 shape so a corrected re-ring can re-acquire; no charge occurred. |
| T-67-SC | Tampering (supply chain) | npm installs | accept | This plan adds NO new dependencies (edits + tests only) — no package-manager installs, so the supply-chain install gate is N/A. |
</threat_model>
