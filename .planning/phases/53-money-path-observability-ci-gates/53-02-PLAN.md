| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-04 | Information Disclosure | tags object at each captureException call site | mitigate | Call sites put ONLY allowlisted ids (reqId, txnId, invoiceId/salesOrderId/invoiceNumber) in tags — never amount/email/token-value; enforced by acceptance grep + the regression test's no-PII assertion; 53-01 `beforeSend` scrubs as defense-in-depth |
| T-53-05 | Information Disclosure | the captured `err` object itself (may embed request body / customer data in err.response.data) | mitigate | 53-01 `beforeSend` (already live in wave 1) strips `event.request.data` and masks emails before send; capture passes the raw err and relies on the global scrub |
| T-53-06 | Denial of Service | over-capturing best-effort catches floods Sentry / obscures real money errors | mitigate | D-01 boundary strictly enforced — only money-movement catches instrumented; acceptance criteria assert OUT-of-scope catches gained no capture; D-04 fingerprint (53-01) collapses bursts to one issue |
| T-53-SC | Tampering | npm supply chain | accept | No new packages installed (`@sentry/node@10.42.0` already present) |
</threat_model>
