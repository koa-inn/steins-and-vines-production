Replace the non-atomic GET-then-SET idempotency check with an atomic lock acquisition. The pattern already exists in the codebase (promo code uses `cache.acquireLock()`).

In the `proceed()` function (around line 120), replace:
```javascript
var cached = await cache.get(idempotencyKey);
if (cached) {
  return res.status(201).json(JSON.parse(cached));
}
```

With:
```javascript
var cached = await cache.get(idempotencyKey);
if (cached) {
  return res.status(201).json(JSON.parse(cached));
}
var lockKey = 'lock:' + idempotencyKey;
var lockAcquired = await cache.acquireLock(lockKey, CHECKOUT_IDEMPOTENCY_TTL);
if (!lockAcquired) {
  return res.status(409).json({ error: 'Checkout already in progress' });
}
```

This ensures that if two requests arrive simultaneously, the second one gets a 409 instead of racing through.

NOTE: Check the acquireLock signature first — it may be `acquireLock(key, ttlSeconds)` or `acquireLock(key, ttlMs)`. Match the existing promo code usage pattern.

Also ensure the lock is released on error (add to the catch block or rely on TTL expiry). Since the TTL is 600s (10 min) and matches the idempotency TTL, auto-expiry is acceptable — the success path writes the real cached response which serves future requests.
  </action>
  <done>Concurrent duplicate requests get 409. TOCTOU window closed.</done>
