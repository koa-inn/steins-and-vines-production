<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Zoho Books -> middleware -> browser | customer_name/email/phone and document_status originate in Zoho (third-party data store, editable by anyone with Zoho access) — untrusted strings rendered into the DOM |
| browser -> Apps Script update_batch | staff-authored mutation; carries Zoho-sourced strings forward into the Batches sheet |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-01 | Tampering/XSS | Refresh handler DOM patch of customer_name/email/phone (bp-detail-customer/email/phone) | mitigate | Run every Zoho-sourced string through brewpad.js `escapeHTML` before innerHTML/textContent insertion; never interpolate raw response fields |
| T-29-02 | Tampering | zoho_so_number rendered into Zoho Ref / Invoice section | mitigate | Already escaped via escapeHTML at render (lines 2228/2238); new button label is static text, soNumber only used in encodeURIComponent for the query string |
| T-29-03 | Information disclosure | x-api-key (MW_API_KEY) sent from GitHub-Pages-served JS | accept | Semi-public by design per project docs (CORS + Referer guard are the real protection); endpoint is read-only and rate-limited (Phase 28 D-11) |
| T-29-04 | Tampering | update_batch payload could carry blank Zoho values and erase batch data | mitigate | buildRefreshUpdates omits all empty fields (D-13 / Phase 28 D-02); compareRefreshFields short-circuits no-op writes (D-12) |
| T-29-05 | Elevation/Repudiation | concurrent edit overwrites newer batch state | mitigate | Send expectedVersion=last_updated (D-13); optimistic-lock conflict surfaces a "reload" toast rather than silently clobbering |
| T-29-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages installed in this plan; if any install is attempted, stop and add a legitimacy checkpoint |
</threat_model>
