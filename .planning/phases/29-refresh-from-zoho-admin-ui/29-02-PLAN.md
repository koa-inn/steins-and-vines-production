<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Zoho Books -> middleware -> admin browser | customer_name/email/phone and document_status are third-party untrusted strings rendered into the modal DOM |
| admin browser -> Apps Script update_batch | staff mutation carrying Zoho-sourced strings into the Batches sheet |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-A1 | Tampering/XSS | Refresh DOM patch of batch-detail-customer/email/phone and the Zoho Ref row | mitigate | Wrap every Zoho-sourced string in admin.js `escapeHTML` before innerHTML/textContent insertion; button label is static text |
| T-29-A2 | Tampering | zoho_so_number in the Zoho Ref row | mitigate | escapeHTML the displayed number; only ever pass it through encodeURIComponent in the query string |
| T-29-A3 | Information disclosure | x-api-key (MW_API_KEY) in GitHub-Pages JS | accept | Semi-public by design (CORS + Referer guard are the real protection); read-only rate-limited endpoint (Phase 28 D-11) |
| T-29-A4 | Tampering | update_batch could write blank Zoho values | mitigate | buildRefreshUpdates omits empty fields (D-13 / Phase 28 D-02); compareRefreshFields skips no-op writes (D-12) |
| T-29-A5 | Elevation/Repudiation | concurrent edit clobber | mitigate | Send expectedVersion=batchVersion (D-13); conflict -> "reload" toast; bump batchVersion from result.newVersion |
| T-29-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages installed; stop and add a legitimacy checkpoint if any install is attempted |
</threat_model>
