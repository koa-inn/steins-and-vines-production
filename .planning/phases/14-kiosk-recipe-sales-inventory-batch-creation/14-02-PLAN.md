**Helper — callAppsScriptPost** (copy from recipes.js, lines 33-50, same pattern):
```javascript
function callAppsScriptPost(action, payload) {
  var url = process.env.APPS_SCRIPT_URL;
  var token = process.env.APPS_SCRIPT_SERVER_TOKEN;
  if (!url || !token) {
    return Promise.reject(new Error('Apps Script not configured'));
  }
  return axios.post(url, JSON.stringify(Object.assign({}, payload, {
    action: action,
    server_token: token
  })), {
    headers: { 'Content-Type': 'application/json' },
    timeout: 15000,
    maxRedirects: 5
  }).then(function (resp) { return resp.data; });
}
```

**POST /api/kiosk/recipe-sale** (initiate — pushes to terminal):

Request body: `{ recipe_id: string, sale_type: 'in-store' | 'take-out', mill_grain: boolean, customer_name?: string, contact_id?: string }`

Flow:
1. **Feature gate** (per D-13, KSK-04): Check `(process.env.BEER_SALES_ENABLED || 'false').toLowerCase() !== 'true'` → 403 `{ error: 'Recipe sales are not enabled' }`
2. **Terminal check**: `!helcimLib.isTerminalEnabled()` → 503 `{ error: 'POS terminal not configured' }`
3. **Input validation**: 
   - `recipe_id` must be a non-empty string → 400 `{ error: 'Missing recipe_id' }`
   - `sale_type` must be `'in-store'` or `'take-out'` → 400 `{ error: 'sale_type must be in-store or take-out' }`
   - `mill_grain` must be boolean (default false) → coerce to boolean
4. **Fetch recipe from Apps Script**: `callAppsScriptPost('get_recipe', { recipe_id: body.recipe_id })` — if `!data.ok` or `!data.data` → 404 `{ error: 'Recipe not found' }`. Check `data.data.recipe.status === 'active'` → 400 `{ error: 'Recipe is not active' }`
5. **Compute server-authoritative total** (per D-08 — terminal charge is the sum of ingredient Zoho rates + applicable fees, NOT locked_price):
   - Sum all ingredient `rate * quantity` from the recipe ingredients (ingredient rates come from the cached ingredients catalog at `C.CACHE_KEYS.INGREDIENTS`, same as availability endpoint does). If catalog cache is cold, return 503 `{ error: 'Ingredient catalog not available — try again shortly' }`
   - If `sale_type === 'in-store'`: add `service_fee` + `materials_fee` from recipe record
   - If `sale_type === 'take-out'` and `mill_grain === true`: add milling fee rate (fetch from cached catalog using `MILLING_FEE_ITEM_ID`; if env var not set → 400 `{ error: 'Milling fee not configured. Contact admin.' }`)
   - Store computed total as `grandTotal` (used for terminal push AND invoice)
6. **Acquire Redis mutex** (per D-04, INV-02): `cache.acquireLock(C.LOCK_KEYS.RECIPE_SALE, 30)` — if `!acquired` → 503 `{ error: 'Another recipe sale in progress — try again in a moment.' }`
7. **Push to terminal**: `helcimLib.terminalPurchase(grandTotal, refNumber)` where `refNumber = 'RECIPE-' + Date.now()`
   - On success → 202 `{ pending: true, reference: refNumber, recipe_id: body.recipe_id, sale_type: body.sale_type, mill_grain: body.mill_grain, total: grandTotal }`
   - On failure → release lock, then 502 `{ error: 'Terminal error — please try again' }`

**POST /api/kiosk/recipe-sale/confirm** (after terminal payment confirmed):

Request body: `{ recipe_id: string, sale_type: 'in-store' | 'take-out', mill_grain: boolean, transaction_id: string, reference: string, card_type?: string, customer_name?: string, contact_id?: string }`

Flow:
1. **Feature gate** (same as initiate)
2. **Input validation**: `recipe_id`, `transaction_id`, `reference` all required → 400
3. **Re-fetch recipe** from Apps Script: `callAppsScriptPost('get_recipe', { recipe_id })` — verify still active
4. **Re-compute total server-side** (same logic as initiate step 5 — never trust client total)
5. **Build invoice line items** (per D-06, D-07, INV-01):
   - One line item per ingredient: `{ item_id: ing.item_id, name: ing.item_name, quantity: ing.quantity, rate: ingredientRate, tax_id: ingredientTaxId }`
   - Ingredient rate and tax_id come from the cached ingredients catalog (same lookup as initiate)
   - If `sale_type === 'in-store'`:
     - Add line: `{ item_id: process.env.MAKERS_FEE_ITEM_ID, name: 'Brewing Fee', quantity: 1, rate: recipe.service_fee }`
     - Add line: `{ item_id: process.env.MATERIALS_FEE_ITEM_ID, name: 'Materials Fee', quantity: 1, rate: recipe.materials_fee }`
   - If `sale_type === 'take-out'` and `mill_grain === true`:
     - Add line: `{ item_id: process.env.MILLING_FEE_ITEM_ID, name: 'Milling Fee', quantity: 1, rate: millingRate }`
6. **Create Zoho invoice**: `zohoPost('/invoices', invoicePayload)` with:
   ```javascript
   var today = new Date().toISOString().slice(0, 10);
   var invoicePayload = {
     date: today,
     reference_number: body.reference,
     payment_terms: 0,
     payment_terms_label: 'Due on Receipt',
     line_items: lineItems,
     notes: 'Kiosk recipe sale (' + body.sale_type + '). Recipe: ' + body.recipe_id + '. Ref: ' + body.reference,
     custom_fields: [],
     customer_id: body.contact_id || process.env.KIOSK_CONTACT_ID || ''
   };
   ```
   On Zoho failure → **void the transaction** (per existing pattern): `helcimLib.voidTransaction(body.transaction_id)` with void failure alert, then release lock, then 502 `{ error: 'Payment was taken but invoice failed. Payment voided.', payment_voided: true }`
7. **Submit invoice** (triggers Zoho inventory deduction per INV-01): `zohoPost('/invoices/' + invoiceId + '/submit', {})` — fire-and-forget `.catch(function(){})`
8. **Record customer payment**: `zohoPost('/customerpayments', { payment_mode: 'creditcard', amount: grandTotal, date: today, reference_number: body.transaction_id, invoices: [{ invoice_id: invoiceId, amount_applied: grandTotal }], notes: 'Kiosk recipe sale. Ref: ' + body.reference })`
9. **Bust caches** (per Pitfall 4): `cache.del(C.CACHE_KEYS.KIOSK_PRODUCTS)` AND `cache.del(C.CACHE_KEYS.INGREDIENTS)` AND `cache.del(C.CACHE_KEYS.RECIPES_TS)`
10. **Release mutex**: `cache.releaseLock(C.LOCK_KEYS.RECIPE_SALE).catch(function(){})`
11. **Fire-and-forget batch creation** (per D-09, D-10, only for in-store): 
    ```javascript
    if (body.sale_type === 'in-store') {
      var snapshot = { name: recipe.name, style: recipe.style, abv: recipe.abv,
        locked_price: recipe.locked_price, service_fee: recipe.service_fee,
        materials_fee: recipe.materials_fee, ingredients: ingredients };
      brewpadIntegration.detectRecipeSale(body.recipe_id, snapshot, invoiceNumber, body.customer_name, body.contact_id);
    }
    ```
12. **Log event**: `eventLog.logEvent('kiosk.recipe_sale_completed', { txnId: body.transaction_id, recipeId: body.recipe_id, saleType: body.sale_type, total: grandTotal, invoiceNumber: invoiceNumber })`
13. **Return receipt**: 201 `{ ok: true, transaction_id: body.transaction_id, invoice_number: invoiceNumber, recipe_id: body.recipe_id, sale_type: body.sale_type, total: grandTotal }`

**CRITICAL: Lock release on every error path** (per Pitfall 1):
- Terminal push failure → releaseLock
- Zoho invoice failure → voidTransaction, then releaseLock
- Void failure → releaseLock (still release even if void fails)
- Any unexpected error → releaseLock in outer .catch

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> /api/kiosk/recipe-sale | Untrusted input: recipe_id, sale_type, mill_grain, total (ignored) |
| client -> /api/kiosk/recipe-sale/confirm | Untrusted input: recipe_id, transaction_id, reference |
| middleware -> Zoho API | Trusted outbound: server-computed amounts only |
| middleware -> Apps Script | Trusted outbound: server_token authenticated |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-03 | Tampering | Client-supplied rate/total in request body | mitigate | Server re-fetches recipe from Apps Script and re-computes total from cached ingredient catalog rates. Client total is IGNORED. (Same pattern as pos.js catalog price anchoring.) |
| T-14-04 | Tampering | Client-supplied recipe_id pointing to draft/inactive recipe | mitigate | Server re-fetches recipe and checks `status === 'active'` before building invoice lines |
| T-14-05 | Spoofing | Unauthorized access to recipe sale endpoint | mitigate | Endpoint covered by existing `requireApiKey` middleware in server.js (all `/api/*` POST routes) |
| T-14-06 | Denial of Service | Mutex lock held indefinitely | mitigate | 30-second TTL on Redis lock; releaseLock called on all error paths (terminal fail, Zoho fail, void fail) |
| T-14-07 | Elevation of Privilege | BEER_SALES_ENABLED bypass | mitigate | Server-side env var check at top of BOTH handlers (initiate and confirm); client-side hiding is UX only |
| T-14-08 | Tampering | mill_grain toggle manipulated for in-store sales | mitigate | Server ignores mill_grain when sale_type is 'in-store'; milling fee only added for take-out |
| T-14-09 | Repudiation | Void failure after Zoho invoice error | mitigate | Follow existing pattern: `mailer.sendVoidFailureAlert()` + Redis `sv:void-failure:` persistence + eventLog |
| T-14-10 | Information Disclosure | recipe_snapshot stored in Batches sheet | mitigate | Snapshot contains only recipe name, style, ABV, fees, ingredient names/quantities — no customer PII (per security_context) |
</threat_model>
