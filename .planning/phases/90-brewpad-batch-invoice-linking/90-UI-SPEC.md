# Phase 90 - UI Design Contract

> Visual and interaction contract for BrewPad invoice linking, the kiosk canning bundle, and the recipe picker dropdown. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: 90-CONTEXT.md (D-01..D-21, locked), 90-RESEARCH.md, `css/brewpad.css` and `css/kiosk.css` `:root` tokens (scouted this session). Where neither locked a choice, this file picks the option closest to existing patterns and lists it under "Open Questions for Owner".

Scope guard: workstream B (grain-order splitting) is Phase 91 and has no UI here. No new palette, no new framework, no new icon set.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (static HTML, vanilla ES5 JS, hand-written CSS; shadcn gate not applicable, not a React/Vite stack) |
| Preset | not applicable |

| Font | `--font-body` Lato, 'Helvetica Neue', Arial, sans-serif for all UI. `--font-display` Georgia only for existing headings; none added in this phase |

Stylesheets touched: `css/brewpad.css` (A, D-BrewPad), `css/kiosk.css` (C, D-kiosk). Admin recipe editor reuses `css/admin.css` classes; only a small additive block if needed. Minified files regenerate via the single final `npm run build`.

## Spacing Scale

Declared values (multiples of 4). Subset of the kiosk `--sp-*` tokens; the legacy 12px `--sp-3` step is not used by any new rule.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between badge and text, chip inner gaps |
| sm | 8px | Gap between action buttons on a candidate card, chip row gap, dropdown row inner gap |
| md | 16px | Card padding, gap between candidate cards, picker field spacing |
| lg | 24px | Confirm-sheet top padding, bundle picker modal padding |
| xl | 32px | Gap between bundle picker sections on kiosk |
| 2xl | 48px | Not used by new components |
| 3xl | 64px | Not used by new components |

Exceptions:
- Touch targets: every tappable control is at least 44px tall (BrewPad `.bp-filter-btn`, `.bp-vessel-option`, kiosk standard). Kiosk bundle picker primary controls use 52px min-height (existing `kiosk` 52px class family) because the iPad is operated at arm's length.
- `.bp-btn-sm` (36px) is NOT used for Link invoice / Not this / Mark internal; those are the primary action of the screen and must be 44px.
- Legacy 12px spacing in `.bp-batch-search-row` (margin) and `.bp-confirm-sheet-actions` (gap) is reused as-is, not restyled. New compact card row gaps use 8px or 16px.
- Existing legacy values (10px, 20px paddings in `.bp-vessel-option`, `.bp-confirm-sheet-inner`) are kept where those classes are reused unchanged; new rules use only the scale above.

## Typography

Phase 90 declares 4 sizes and 2 weights. These are the subset of the existing rem scale (0.75 / 0.875 / 1 / 1.25 rem at 16px root) that new rules may use.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (card text, line items, dropdown option, input text) | 14px (0.875rem) | 400 | 1.5 |
| Label (chip text, badge, meta such as date / paid status, helper and warning text) | 12px (0.75rem) | 700 | 1.4 |
| Heading (card title = invoice number, picker section title, confirm-sheet message) | 16px (1rem) | 700 | 1.2 |
| Display (kiosk bundle price in picker, kiosk bundle cart line total) | 20px (1.25rem) | 700 | 1.2 |

Weights: 400 regular + 700 bold only (existing buttons and filter chips already use 700). No 600 or 500.
Exception: reused existing classes retain their own sizes (e.g. `.bp-filter-btn` 0.8rem, `.bp-confirm-sheet-msg` 1.05rem); do not restyle them. New rules must use the table above.
Kiosk text is 14px minimum for body (existing kiosk body is 0.85-1rem); do not go below 12px anywhere.

## Color

Reuse the existing cellar palette from `:root` in `brewpad.css` / `kiosk.css`. No new hex values are introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--cellar-canvas` #e8e2ca / `--cellar-surface` #f5f1e6 | Page background, detail view background |
| Secondary (30%) | `--cellar-raised` #faf8f2 with `--ledger-emphasis` border | Candidate cards, dropdown panels, bundle picker modal, confirm sheet |
| Accent (10%) | `--stain` #370e13 (primary action fill, active chip) | Reserved list below |
| Destructive | `--batch-danger` #a83232 | Destructive actions only |

Accent (`--stain`) reserved for:
1. The active "Unlinked" filter chip (`.bp-filter-btn--active`, existing behaviour).
2. The one primary action button per surface: "Link invoice" on a candidate card, "Create batch" in the create sheet (existing), "Add to cart" in the kiosk bundle picker. "Start from this recipe" is NOT accent (secondary outline).
3. The selected state of a segmented option in the kiosk bundle picker (`.kiosk-bundle-opt--active` fill). This is a selection indicator, not an action button, so it does not conflict with rule 2: at most one accent action button plus the selected segmented options are visible together.
4. The kiosk recipe-mode tile highlight (2px `--stain` outline for 2 seconds after choosing from the dropdown).
5. Focus ring (`--ledger-focus`) on the invoice / recipe search inputs (existing).

Semantic colours (existing tokens, used only for the meaning stated):
- `--batch-success` / `-bg`: invoice status "Paid" pill.
- `--batch-warning` / `-bg`: "already linked to SV-B-xxx" notice, kiosk over-cap warning, duplicate recipe name warning, "link status unknown".
- `--batch-danger` / `-bg`: error banners (`duplicate_so_number`, Zoho failure) and destructive confirm only. Mark internal is NOT destructive (reversible via D-05); it uses secondary outline, not danger.
- `--batch-info` / `-bg`: "Internal" source badge (neutral informational).
- `--ink-tertiary` / `--ink-muted`: unpaid / draft status text, "Not this" button text.

Accent is never applied to: Not this, Mark internal, status pills, badges, dropdown rows, or the "Canning bundle" opener button (that uses the existing secondary button style).

## Interaction Contracts

### A1. Create-batch sheet (D-01..D-04)

Layout order, below the existing customer field:
1. Label "Invoice (optional)".
2. Search input, placeholder "Search invoices by number or customer". Pre-filled with the customer text already typed; re-seeded when the customer field changes and the invoice is still unset. Search starts at 2+ characters (server minimum); debounce per existing `fetchSoSearch` behaviour.
3. Results in `.bp-vessel-dropdown` rows: invoice number, date, customer. If the invoice already has batches (from `_allBatchesData`), the row shows a warning line "Already linked to SV-B-000063" (D-09). Row is still selectable.
4. On select: input is replaced by `.bp-linked-chip` "INV-xxxxxx x". Selection populates hidden fields only; no write happens until Create batch.
5. Checkbox row (44px tall, whole row tappable): "No invoice (internal batch)". Checking it disables and clears the invoice search and chip. Choosing an invoice unchecks it.

States:
- Submit with invoice chosen: sends `zoho_so_number` and `customer_id`.
- Submit with checkbox checked: sends `source: 'internal'`.
- Submit with neither: `showConfirmSheet("Create without invoice?", "Create batch", primary)` plus Keep editing. Message sub-line: "You can link an invoice later from the batch."
- Invoice search loading: one muted row "Searching...". No results: muted row "No invoices found. Check the spelling, or tick No invoice (internal batch)." Error: danger-tinted row "Invoice search failed. Try again."
- `duplicate_so_number` on create: inline danger banner above the submit button: "That invoice already has a batch for this product (SV-B-000063). Create without an invoice and link it from the batch instead." Submit button re-enables. Do not auto-retry.
- Other create error: existing create error handling, unchanged.

### A2. "Unlinked" filter chip (D-06)
- Third chip in the existing row, label "Unlinked" with count in the same format as Pending: "Unlinked (57)". Active state uses `.bp-filter-btn--active`.
- Counts all non-disabled batches with empty `zoho_so_number` and source not `internal`, all statuses.
- Empty state (list reaches zero): heading "Every batch is linked", body "Batches without an invoice are marked Internal."
- Chip hidden count is not hidden at zero; it shows "Unlinked (0)" so staff see completion.

### A3. Batch detail guided review (D-07..D-10)

Shown only when the open batch is unlinked (empty `zoho_so_number`, source not `internal`). Placed in the detail view directly under the existing "Link to Invoice" control; the existing manual search button remains as the fallback ("Search all invoices").

Section title (Heading): "Possible invoices". Sub-line (Label, `--ink-secondary`): "Same customer, within 60 days of the start date. Nothing is saved until you tap Link invoice."

Candidate card content (up to 3, ranked by date distance, Maker's Fee/kit invoices first per RESEARCH A7):
- Head: invoice number; right side paid-status pill ("Paid" ok, "Unpaid" muted, "Part paid" warn, "Overdue" warn).
- Meta: date (e.g. "12 Aug 2026"), total ("$85.50"), and "N days from start" in Label.
- Line items list.
- If `linked_batches` non-empty: `.bp-link-card-warn` "Already linked to SV-B-000063". Button label stays "Link invoice" (deliberate double link is allowed, D-09). If `linked_batches` is null: muted Label "Link status unknown". Never blocks Link invoice.
- If no Maker's Fee line: Label "No kit or fee line" in `--ink-tertiary` (so the human can judge).
- Actions: Link invoice | Not this | Mark internal. "Mark internal" is hidden when the batch source is locked (kiosk, kiosk_recipe, online, zoho_scan, research).

Behaviour:
- Link invoice: writes `zoho_so_number` only (never customer or product). Button shows "Linking..." and is disabled. On success the card section is replaced by the existing "Linked to INV-xxxxxx" display and a toast "Linked to INV-xxxxxx". On failure: inline danger row on that card "Could not link. Try again." with the buttons re-enabled.
- Not this: card is removed immediately (no confirm), remaining cards shift up. Persisted locally per batch. When all hidden: empty state below.
- Mark internal: no confirm sheet (reversible: the batch detail shows a "Mark as not internal" text action that sets `manual`). On success the section collapses to an "Internal" source badge; the batch drops out of the Unlinked list.
- Loading: 3 skeleton cards (static `--ledger-soft` blocks, same height as a card, no shimmer animation) and Label "Looking for invoices...".
- Empty: "No matching invoices found" with body "Try Search all invoices, or mark this batch Internal if it was made for the shop." Buttons: "Search all invoices" (secondary) and "Mark internal" (secondary).
- Error (Zoho busy / 502): danger-tinted row "Invoice lookup failed. Zoho may be busy, try again in a minute or search manually." with "Try again" and "Search all invoices".
- No customer on the batch (blank or Walk-In): skip lookup; show the empty state with body "This batch has no customer, so no invoices can be suggested."
- Source badge: `.bp-source-badge--internal` ("Internal") shown in the detail header and on the list row beside existing badges (alongside the kiosk badge position at `brewpad.js:575`).

### C. Kiosk canning bundle (D-11..D-16)

Opener: a "Canning bundle" secondary button (52px) in the kiosk product/cart tool area beside the existing custom-item and discount controls. Must exist on both kiosk.html and the admin-embedded kiosk panel (RESEARCH Open Q6).

Picker modal (reuses custom-item modal shell), single column, order:
1. Title "Canning bundle" (Heading). Close `&times;` 44px.
2. Section "Batch type": two segmented buttons "Beer 25 L" and "Cider / sparkling wine 23 L". Price shown on each in Label: "$40.00" / "$35.00" ("+ 12% tax" in Label beneath the pair). No default selected; Add to cart disabled until chosen.
3. Section "Can size": "473 mL" and "355 mL" segmented. No default.
4. Section "Cans filled": stepper pre-filled with nominal when type and size are both chosen (beer 52 / 70; cider 48 / 64); updates the prefill only if the operator has not edited it. Helper Label: "Nominal for this batch: 52 cans".
5. Over-cap inline warning (D-12) appears live when count exceeds cap (beer 55 / 72, cider 50 / 68): warning block "Above the bundle cap. Confirm this is one batch." with a checkbox row "Yes, this is one batch" (44px+). Add to cart stays disabled until ticked. Price still shows the flat bundle price; no per-can fallback text.
6. Footer: Go back (secondary) and "Add to cart" (primary, accent). Total preview in Display: "$40.00 + $4.80 tax".

Cart result (two lines, grouped visually with a shared left border in `--cork`):
- Line 1: "Canning Bundle — Beer 25 L (473 mL)" (exact label format from CONTEXT), "12% tax" Label, price "$40.00". No quantity stepper (fixed 1). Remove button.
- Line 2: can item name, "x 52", price "$0.00" with Label "Included in bundle". Quantity stepper allowed (changes only this line, never the price). Stepper changes re-run the cap check: crossing the cap shows the same inline warning on the line with an "OK, one batch" button; no modal `confirm()`.
- Removing either line removes both (D-16). Tapping remove on the bundle line while a can line exists needs no extra confirm; the removal is silent and both rows disappear. Clear-cart clears both.
- Only one bundle per cart (assumption, Open Question 1). Opener shows "Bundle added" disabled state while one is in the cart.
- Discount UI: unchanged. The bundle line shows no discount; Label "Not discountable" is NOT added (avoid new copy; existing custom lines already behave this way).

Failure states: if the server rejects the sale for a bundle total mismatch, the existing kiosk sale-error banner is used with copy "Sale not completed. The bundle total did not match, nothing was charged. Remove and re-add the canning bundle, or call the owner." (exact reuse of the existing error surface, new copy only).

### D. Recipe picker dropdown (D-19, D-20)

Shared behaviour for BrewPad new-batch Recipes tab, BrewPad attach-recipe, and (recommended, near-zero cost) the two waitlist pickers:
- Field placeholder "Search or choose a recipe".
- Focus OR click opens the full list (add a `click` listener; iPad Safari does not re-fire `focus` on an already-focused input). No 15-item cap.
- Panel: `.bp-vessel-dropdown` rules (max-height 200px on BrewPad phone-width, raised to 320px when the viewport is at least 768px wide). Scrolls inside the panel.
- Row: recipe name on the first line (Body role, 14px, weight 700), style on the second line (Label role, 12px, weight 700, `--ink-secondary`). Row min-height 44px, 4px gap between lines.
- Sort: case-insensitive by name. Baseline is a flat list; no grouping by `beer_category` (optional, see Open Questions).
- Typing narrows the list (case-insensitive match on name or style). No match: single muted non-selectable row "No recipes match. Clear the search to see all."
- Loading (first open): single muted row "Loading recipes...". Fetch failure: danger-tinted row "Could not load recipes. Tap to retry."
- Selection: `mousedown` / `touchstart` as in the current code, then the panel closes and the field shows the chosen name. Escape and tap outside close the panel.
- On the new-batch sheet, the recipe dropdown opens on focus only while the Recipes tab is active (keep the existing `_productPickerTab` guard).

Kiosk recipe mode: a search field (`.kiosk-recipe-search`, 52px) above `#kiosk-recipe-grid`, same dropdown behaviour. Choosing a recipe in the dropdown scrolls to and highlights the matching grid tile (2px `--stain` outline for 2 seconds) and applies the same action as tapping the tile. Typing also filters the grid itself (hides non-matches); clearing the field restores all tiles. Panel row height 52px on kiosk.

### D-21. Recipe editor, new recipe
- As the name is typed (debounced 200ms, 2+ characters), a "Similar recipes" list appears under the name field (max 5 shown, scroll beyond), name and style per row, each row with a "Start from this recipe" secondary button (44px).
- Exact case-insensitive trimmed match shows `.bp-recipe-dup`: "A recipe named 'Pale Ale' already exists." (warning only; saving is not blocked; owner may want a duplicate).
- "Start from this recipe": if the form is dirty, `showConfirmSheet("Replace what you have entered with a copy of 'Pale Ale'?", "Start from copy", primary)`. If clean, proceed without a confirm. Result: fields populated from `bpCloneRecipePayload` (name becomes "Copy of Pale Ale", status draft), the similar list closes, and focus moves to the name field with its text selected.
- Applies to both the BrewPad editor (`#bp-recipe-name`) and the admin editor (`#recipe-name`). Loading a source recipe shows the button as "Loading..." disabled; failure shows danger row "Could not load that recipe. Try again."
- Hidden entirely when editing an existing recipe (new-recipe mode only).

### D-18. custom-labels.html
Copy only, no layout change. Replace `~84 cans (355 mL)` at line 161 with: "about 70 x 355 mL cans or about 52 x 473 mL cans for a 25 L beer batch". Use the existing multiplication character convention already used on that page if different from "x".

## Accessibility and Touch

- All controls 44px minimum (kiosk 52px). Checkbox rows are fully tappable.
- Candidate actions are real `<button>` elements with visible text; the `&times;` clear controls carry `aria-label` ("Clear invoice", "Close").
- Warnings and errors use `role="alert"` on insertion; loading rows use `aria-busy`.
- Dropdowns: input has `role="combobox"`, `aria-expanded`, `aria-controls`; panel `role="listbox"`, rows `role="option"`.
- Colour is never the only signal: pills, warnings and badges always carry text.
- Contrast: use `--ink-muted` as redefined in brewpad.css (#7a6654, WCAG-darkened). The kiosk file still defines `--ink-muted: #b8a898`, which fails AA on `--cellar-canvas`; do not use it for new kiosk text, use `--ink-tertiary` instead.

## Open Questions for Owner

Each is an assumption made in this spec with a recommended default. None block planning.

1. Multiple bundles per cart. Assumption: one bundle per cart (fixed keys `bundle-line` / `bundle-can`); opener disables once added. Default: one. Change if a customer ever cans two batches in a single sale.
2. "Not this" persistence. Assumption: hidden per batch in localStorage (RESEARCH A6), not shared across devices. Default: localStorage.
3. Non-kit invoices in candidates. Assumption: shown, ranked after Maker's Fee invoices, flagged "No kit or fee line" (RESEARCH A7). Default: show flagged.
4. Waitlist pickers. Assumption: the two waitlist recipe pickers get the same full-list dropdown because they share the defect and code. Default: include (low cost).
5. Mark internal without a confirm sheet. Assumption: one tap, reversible via "Mark as not internal". Default: no confirm. Switch to a confirm if the owner prefers.
6. Create-sheet picker adds `customer_id` to the payload (RESEARCH A4). No visible UI change.
7. Grouping the recipe dropdown by `beer_category` (CONTEXT discretion). Default: flat alphabetical list, no groups. Revisit once Phase 89 categories are populated.
8. Cap override UX. Assumption: a tick-box ("Yes, this is one batch") must be ticked before Add to cart, rather than a second dialog. Default: tick-box, non-modal.
9. Bundle picker has no default type or size (forces a deliberate choice, avoids a wrong-price sale). Alternative: preselect Beer 25 L / 473 mL. Default: no preselection.
10. Kiosk panel inside admin.html: the "Canning bundle" opener and picker DOM must also be present there (shared `kiosk-core.js`). Default: yes, injected by shared code or duplicated markup per RESEARCH Open Q6.
11. Candidate card limit is 3 per D-07; if the window yields more than 3, extra candidates are not reachable except via "Search all invoices". Default: 3.
12. Kiosk tile highlight after choosing from the recipe dropdown (2px outline for 2 seconds) is new behaviour. Default: include; drop if it conflicts with the existing tile selection state.
13. Dropdown panel height 200px phone / 320px tablet: the 320px value is new. Default: keep, because kiosk and iPad BrewPad users scan up to about 100 recipes.
14. Typography: the declared 4-size subset is narrower than the sizes in the existing CSS (0.78, 0.82, 0.85, 0.9, 0.95rem exist). New rules use only the declared subset; reused legacy classes keep theirs. Default: as stated.
