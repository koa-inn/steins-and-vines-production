<objective>
Add the read-only candidate-invoice lookup that powers the batch-detail guided review, and harden the staff
create path so `source` can only be manual or internal.

Purpose: D-07..D-10 (server tier of the review; the UI is Plan 90-06, which codes against the response
contract below) and research optional hardening A5 for D-04/D-05 (accepted here as defence in depth: no
staff flow legitimately posts another source through the proxy; only js/brewpad.js calls create_batch).
Do NOT extend /api/batch/scan-invoices (it is the inverse direction and skips already-linked invoices);
reuse its pieces (auth wrapper, capped sequential detail fetch, detectKitItems).
Output: lib/batch-link-candidates.js (pure), the route in pos.js, the coercion, three new test files.

Response contract (Plan 90-06 consumes exactly this):
`GET /api/batch/link-candidates?customer_id=&customer_name=&start_date=YYYY-MM-DD` ->
200 `{ candidates: [{ invoice_id, invoice_number, date, total, status, balance, customer_name, has_kit_line, line_items: [{ name, quantity, rate }], linked_batches: ['SV-B-000063'] | null, date_distance_days }], index_available: true|false, inspected_all: true|false, uninspected_count: N, reason?: 'no_customer' }` (inspected_all/uninspected_count describe the detail-fetch cap; on the no_customer path inspected_all is true and uninspected_count 0);
400 `{ error: 'bad_request', message }`; 502 `{ error: 'Invoice lookup failed' }`.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-90-17 | Spoofing / Elevation | link-candidates | mitigate | requireTiers(['legacy','session']) like every BrewPad GET; device tier rejected |
| T-90-18 | Tampering (injection) | Zoho query params | mitigate | regex/length validation (digits id, <=100 name, YYYY-MM-DD date); object params to zohoGet (axios encodes), never path concatenation |
| T-90-19 | Denial of Service | Zoho quota | mitigate | server constants: 1 list + max 10 sequential detail calls, 10-minute cache, no prefetch; 502 surfaced to UI |
| T-90-20 | Information disclosure | logs / cache keys | mitigate | no customer names in logs; cache key uses id or truncated sha256 of the normalised name |
| T-90-21 | Integrity | unattended links (D-10) | mitigate | route is read-only (test asserts no write calls); writes only via staff-tapped update_batch in Plan 90-06 |
| T-90-22 | Tampering | staff-set automated source on create | mitigate | hardenProxyPayload coerces create_batch source to manual/internal |
| T-90-23 | Information disclosure | candidate data to staff | accept | same trust level as existing search-invoices (staff session already sees all invoices) |
