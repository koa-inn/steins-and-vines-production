# Steins & Vines — Consolidated Engineering Audit

*Independent adversarial verification was applied to high/critical findings. **Zero findings were refuted** (every verified finding returned `isReal: true`). Three findings were severity-adjusted **down** by the verifier and are placed at their adjusted level; one was confirmed at critical.*

## 1. Executive Summary

- **The entire API-key authorization model is effectively no authorization.** The shared admin key (`MW_API_KEY`, identical to Railway `API_SECRET_KEY`) is committed in plaintext in `js/sheets-config.js` and served raw on public GitHub Pages. Anyone can read all customer PII and create/modify/delete orders, invoices, POs, and gift cards. Treat as compromised and rotate now.
- **The kiosk POS money path is materially weaker than online checkout.** Unlike `checkout.js` (atomic locks, replay protection, fail-closed, void-on-reject), the kiosk paths (`pos.js`) lack atomic idempotency, swallow payment-recording failures while returning success, and orphan charges on terminal timeout — the same incident class as the original orphaned-charge bug, just via different triggers.
- **Gift-card split-tender can silently underpay an order.** Applied gift amount is never validated against the certificate's real balance before charging the reduced terminal amount; a last-step redeem failure leaves the customer underpaid with no `needs_manual_review` flag (Apps Script does protect the balance itself, so loss is bounded to the shortfall).
- **Redis outage removes throttling and double-submit protection simultaneously.** Every rate limiter (PIN brute-force, payment, public checkout) and the distributed locks/idempotency all fail open during a Redis outage — and the code comments claiming a MemoryStore fallback are factually wrong.
- **Observability has a blind spot exactly where it matters.** Sentry is wired only as an Express error handler, but every money-path handler catches its own error and never re-throws, so charged-but-not-recorded / void-failure events produce only a log line, no alert.
- **CI does not protect what ships.** No workflow rebuilds or verifies the tracked minified artifacts GitHub Pages actually serves, so a merged, tested money-path fix can silently fail to go live behind a stale bundle.

## 5. Systemic Themes

- **Two-tier money path maturity.** `checkout.js` is the gold standard (atomic `acquireLock`, transaction-id replay protection, fail-closed-in-prod, `rejectWithVoid` on every early reject) — and the kiosk path in `pos.js` re-implements the same flow *without* those guards. Nearly every High money finding is "kiosk lacks what checkout already has." The structural fix is to extract the checkout safety primitives (lock acquisition, error-propagating payment recording, void-on-failure) into shared helpers both routes use, rather than maintaining two divergent flows.
- **Fail-open under Redis degradation is pervasive and mis-documented.** Rate limiting, distributed locks, and idempotency all silently disable themselves during a Redis outage — the exact moment defenses are most needed — and multiple code comments assert a MemoryStore/single-instance fallback that does not exist. This is a single architectural decision (fail-open vs fail-closed) that was never made deliberately per call-site; the PIN brute-force and double-charge guards in particular should be fail-closed or have a process-local fallback.
- **Authorization rests on a shared static secret shipped to the browser.** The critical finding is not an isolated leak but a model choice: a single key both authenticates and is distributed in public assets, and the surrounding mitigations (CORS, Referer guard, constant-time compare) are individually bypassable or moot. The team already runs Google OAuth for Sheets — server-side identity is the durable fix.
- **Observability and CI don't cover the highest-consequence paths.** Sentry only catches what reaches Express (and nothing on the money path does); E2E never completes a charge and skips PRs; CI never verifies the artifacts that actually ship; the largest money route and the two largest frontend money surfaces have no coverage floor. The safeguards exist in code but the *signal* that they're working — or that a fix is live — is missing.
- **Replay/dedup is a recurring gap on the webhook + terminal boundary.** No webhook timestamp-freshness or event-id dedup, collect-flow double-recording on redelivery, fresh Helcim idempotency keys minted per call, and an `APPROVED`-assuming fallback. A single per-event/per-transaction idempotency layer (SET NX a processed marker before work) would close several Medium findings at once.
- **Repeated "documented standard, then violated" pattern.** The team has explicit, well-applied standards (≥16px iOS guard, 44px touch targets, ES5-only, per-file money coverage floors) — and the findings cluster precisely where those standards weren't generalized to the kiosk/admin tablet surfaces. The gap is enforcement (lint rules, CI floors, shared CSS tokens), not awareness.
